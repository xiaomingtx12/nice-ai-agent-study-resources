Agent 开发平台主线文档定义

当前版本已经采用两条关键约束：记忆系统并入 Agent 主线；Workflow 保持独立成篇。

Mainline Docs

01 平台定义与总览

作用：先讲这个平台到底服务谁、解决什么问题、核心资产有哪些。

业务主线：用户创建应用 -> 配置模型/工具/知识库/工作流 -> 调试 -> 发布 -> 多端使用。

旧内容来源：现有项目总览 + 整体架构中的全局叙事。

02 配置资产与平台底座

作用：讲平台为什么不是一堆页面，而是一组可装配、可发布、可复用的配置资产。

实现重点：应用配置、模型配置、工具配置、知识库配置、工作流配置、版本与发布态。

旧内容来源：多模型集成、工具调用、可视化工作流、整体架构里的配置驱动部分。

03 Agent 运行时与记忆机制

作用：讲一条对话请求进入平台后，怎样真正跑起来。

业务主线：加载应用配置 -> 装配模型和工具 -> 取短期上下文 -> 注入长期摘要 -> 选择执行模式 -> 输出事件流 -> 异步更新记忆。

旧内容来源：核心 Agent 层 + 多模型集成 + RAG 文档里关于会话记忆的部分。

04 工具与外部能力平台

作用：讲平台怎么把外部能力收口成统一运行时接口。

实现重点：Builtin / API / MCP 三类工具的注册、调试、鉴权、执行和 Agent / Workflow 复用。

旧内容来源：工具调用 + 准备文档里的插件工具平台实现详解。

05 知识库与检索链路

作用：只讲平台如何生产和消费外部知识，不再把记忆混进来。

业务主线：文档上传 -> 解析切分 -> 建索引 -> 查询召回 -> 融合重排 -> 作为 Tool 或上下文复用。

旧内容来源：在线知识库设计 + 准备文档中的 RAG 实现详解。

06 Workflow 编排引擎

作用：把 Workflow 作为平台第二条正式执行内核来讲，而不是附属画布。

业务主线：前端 DSL 编辑 -> draft_graph 保存 -> 调试运行 -> 严格校验 -> 发布 graph -> 工具化复用。

旧内容来源：可视化工作流 + LangGraph 编排骨架 + 准备文档里的工作流实现详解。

07 发布、治理与异步执行

作用：补齐一个平台从 demo 走向可交付系统的约束层。

实现重点：多租户、API Key 隔离、后台任务、发布门禁、预算控制、观测性、失败恢复。

旧内容来源：整体架构 + 多模型集成 + 准备文档里的队列/后台处理材料。

08 场景模板与手搓路线

作用：把前面拆开的能力重新装回几个可落地场景，形成真正的手搓指南。

业务主线：客服、知识助手、内容生产等模板分别需要哪些底座、哪些能力、哪些取舍。

旧内容来源：现有总览里提到的模板能力 + 新增的工程落地总结。
