# Learn Claude Code 锐评

先说结论：这条资源很有特点，而且特点强到几乎不可能替代。

它不是那种“把 Agent 世界讲全”的材料，而是非常明确地把 Claude Code 这种产品倒过来拆给你看。你如果正好想知道一个好用的 coding agent 为什么好用，它的命中率会很高；但如果你想找的是一套中性、平铺直叙的 Agent 入门教材，它未必最适合。

## 我觉得它最值钱的地方

第一，它把注意力放在 harness，而不是神化模型本身。仓库 README 里那句意思非常明确：模型决定什么时候调工具、什么时候停，而工程真正要做的是把 loop、tools、knowledge、compression、subagents、tasks、teams 这些外层机制搭起来。

第二，它的教学切法很像产品反向工程。不是先给一堆抽象定义，再慢慢落实现，而是从一个最小 loop 开始，一节节把 Claude Code 的关键体验拆成可以理解、可以实现的模块。

第三，它有“心智模型优先”的意识。README 里把文档写成 `problem -> solution -> ASCII diagram -> minimal code` 的结构，这对学习者很友好，因为你不容易一上来就淹死在代码细节里。

## 我保留意见的地方

第一，它的视角非常聚焦，这既是优点，也是边界。它适合学 harness，但如果你想系统补 Agent 全景，比如评估、记忆体系、生产治理、企业约束，它就不是最全的一条线。

第二，它对 Claude Code 这一对象的依赖很强。虽然作者一直在往“通用 harness 原理”上提炼，但很多吸引力本身就来自“我在拆 Claude Code”。如果你对这一类产品没有使用经验，很多点会少一层切身感。

第三，官网中文站当前目录已经往 `s19` 扩展，但 GitHub README 里主要还是用 `s01-s12` 的阶段图在介绍整体结构。这不算致命问题，但说明项目演进很快，站点和仓库总览偶尔可能不是完全同步的。

## 值不值得投入时间

如果你已经在用 coding agent，或者你想学的根本不是“怎么调用模型”，而是“一个 agent harness 怎么做出来”，那它很值得。

如果你现在缺的是一张更广的 Agent 地图，或者你还没建立最基础的单 Agent 认知，它就不该是最先读的那条资源。

## 我会怎么用它

- 把它当作 Claude Code 类产品的机制拆解课
- 和更偏地图型、架构型的资源搭配着看，避免视角过窄
- 抓它里面可迁移的 harness 模式，而不是执着于“原样复刻 Claude Code”
