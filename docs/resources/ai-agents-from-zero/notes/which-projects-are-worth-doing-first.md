# 项目篇里哪些项目真值得先做

- 来源：[https://didilili.github.io/ai-agents-from-zero/#/](https://didilili.github.io/ai-agents-from-zero/#/)
- 参考仓库：[https://github.com/didilili/ai-agents-from-zero](https://github.com/didilili/ai-agents-from-zero)

## 我不会把所有项目一视同仁

这条资源的项目和案例很多，广度是优点，但也意味着你必须主动取舍。

如果我把项目按“学习价值”而不是“看起来热闹”来排，我会优先做三类：

1. 能快速建立完整闭环感的工作流项目
2. 能逼你理解框架状态流转的 LangChain / LangGraph 项目
3. 能把检索、编排、服务化揉在一起的综合项目

## 第一类：先做工作流型项目，但不要停在平台熟悉度

仓库里有一组很适合先上手的内容，比如 `案例与源码-1-Coze&Dify工作流智能体`，以及 README 里提到的 Coze / Dify 平台项目。

我会优先拿这类项目热身，因为它们能很快回答几个关键问题：

- 一个真实任务到底怎么拆成多步
- 工具、知识库、工作流节点怎么接起来
- 用户输入到最终结果之间，哪一步最容易漂

但我不会在这里停太久。  

因为这类项目最容易让人高估自己：你做出来了一个流程，不代表你已经理解了 Agent 的可迁移机制。

## 第二类：LangChain / LangGraph 项目最值得用来补“框架手感”

如果我只能在后面再选一个方向继续深入，我更愿意优先碰 `案例与源码-2-LangChain框架` 和 `案例与源码-3-LangGraph框架` 这一组。

原因很直接：这两组更容易逼你正面理解状态、工具、检索、链路编排，而不是只学会平台按钮。

具体来说：

- LangChain 更适合练模型接入、提示词模板、链式调用、记忆、工具和检索这些基本构件
- LangGraph 更适合练状态、节点、边、分支和带控制感的工作流组织

如果你做完这两组，还说不清状态在哪保存、工具结果怎么回流、检索在哪一层介入，那说明项目做了，但关键机制还没吃进去。

## 第三类：综合项目最值钱，但不适合排第一

仓库里像 `实战项目-电商问数`、`实战项目-深度研搜`，以及 README 里提到的企业级 RAG / Agent 项目，学习价值很高。

因为它们不再只练某一个点，而是把这些能力放进一条更完整的工程链路里：

- 检索
- 编排
- 服务接口
- 存储
- 评估或效果反馈

但我不会把它们放第一位。  

原因是如果前面的工作流和框架层手感没起来，综合项目很容易变成“照着走了一遍”，最后只留下仓库结构印象。

## 我会延后的项目类型

我会刻意往后放两类内容：

- 主要用于熟悉某个平台界面或部署流程的内容
- 看起来很完整，但你很难从中提炼通用模式的单次案例

不是说它们没用，而是它们更适合在你已经有一点判断框架之后再碰。

## 如果只能做 3 个项目

如果时间很紧，我会这样选：

1. 一个 Coze / Dify 工作流项目  
先把“任务如何拆、节点如何串、知识库如何介入”建立起来。

2. 一个 LangChain 或 LangGraph 案例  
强迫自己进入更底层的状态和控制流理解。

3. 一个综合项目，比如电商问数或深度研搜  
看看检索、编排、服务化放到一起后，复杂度到底怎么长出来。

这三步组合起来，才比较像“从平台体验 -> 框架理解 -> 工程整合”的完整学习路径。
