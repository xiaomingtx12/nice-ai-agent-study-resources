# CodexGuide 锐评

先说结论：这条资源很适合收，而且更适合放在“学习地图”这一层，而不是架构白皮书那一层。

它最强的地方，不是讲得有多深，而是把 Codex 该怎么开始、怎么接入真实工作流、怎么沉淀成团队方法，拆得很完整。

## 我觉得它最值钱的地方

第一，它是明确的路径型资源。不是把所有材料平铺给你，而是把学习路线、入口地图、配置专题、实践方法和案例库串起来，这对第一次上手 Codex 的人很有用。

第二，它对真实工作流的覆盖很实。README 里直接把目标写成“开始、交付、沉淀”，并且把 `AGENTS.md`、沙盒、审批、MCP、Skills、Subagents、团队 playbook 都纳进来了，这比纯速查表有价值得多。

第三，它是持续维护型内容。站点里会标最后核对日期，官方资料索引也一直挂着，这说明它不是一次性写完就放着不管的静态页面。

## 我保留意见的地方

第一，它的范围很大。覆盖面广是优点，但也意味着某些章节会更偏入门与操作，而不会把底层机制讲得很深。

第二，它更像使用指南，不是系统架构教材。如果你现在想学的是 coding agent 的 runtime、权限模型或产品边界分析，它不是最高优先级。

第三，Codex 相关官方资料和产品形态变化会很快，所以这类资源需要定期回头核对。它的价值在于给你路线，不在于替你冻结所有细节。

## 值不值得投入时间

如果你正准备把 Codex 真正用进项目、团队或日常任务里，它值得，而且优先级不低。

如果你现在只是想先补 Agent 理论或更底层的 harness 结构，它可以先放后面。

## 如果时间有限，先从哪部分入手

- 先看学习路线，确认自己的入口
- 再看入口地图和配置专题，尤其是 `AGENTS.md`、沙盒与审批
- 最后看实践方法和实战案例，把 Codex 变成可复用流程
