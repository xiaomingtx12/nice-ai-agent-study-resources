# agent-qa 编码后验证工作流

- 官方指南：[编码智能体测试工作流](https://vostride.com/docs/agent-qa/guides/coding-agent-workflow)
- 配置入口：[快速开始](https://vostride.com/docs/agent-qa/quickstart) · [编码智能体接入](https://vostride.com/docs/agent-qa/coding-agents)

## 这条资源解决什么问题

编码智能体修改应用后，需要在运行中的应用里证明改动有效。agent-qa 的官方指南把这一步拆成找测试、执行、读证据、修复原因和复验，适合已经开始用 AI 编程、准备补上验收流程的人。

agent-qa 支持网页、Android 和 iOS 测试。MCP（模型上下文协议）把测试和证据读取能力提供给编码智能体；memidex 持久记忆保存项目事实与可复用流程，经验证的自我改进把有效经验转为后续运行可用的知识。

## 建议怎么读

1. 按快速开始配置模型与应用，再接入 MCP 和配套技能。
2. 选一处真实改动，明确预期行为，找到或编写覆盖它的最小测试。
3. 运行测试，记录运行编号、判定及支撑判定的截图、控制台或网络证据。
4. 失败时定位应用、测试步骤或环境中的原因；修复后重跑，保留仍未解决的问题。
5. 回看可复用知识，确认经验仍适用于当前应用版本。

## 使用边界

文档要求以实际执行结果判断是否通过。跳过、取消或未执行的检查不能作为通过证据，也不能为了得到通过结果而删弱断言。

工具需要 Node.js 24 或更新版本、模型配置和可运行的测试环境。模型及其他服务费用随配置和用量变化；运行时许可证为 FSL-1.1-ALv2。本文依据官方文档整理，具体项目的测试覆盖与环境适配需要实际验证。
