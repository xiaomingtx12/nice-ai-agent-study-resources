# Agentic Design Patterns

- 官网：[https://adp.xindoo.xyz/](https://adp.xindoo.xyz/)
- 项目仓库：[https://github.com/xindoo/agentic-design-patterns](https://github.com/xindoo/agentic-design-patterns)
- 我当前的定位：把它当作一份 Agent 设计模式索引，用来补“模式语言”和工程判断

## 这条资源在讲什么

这条资源的重点不是从零教你调通一个 Agent demo，而是把 Agent 系统里反复出现的设计模式拎出来讲清楚。

它更像一份模式手册：当你已经知道工具调用、工作流、规划、多 Agent、记忆这些词之后，继续追问它们在系统里到底该怎么组合、边界在哪里、什么时候值得用，什么时候只是把简单问题复杂化。

所以我不会把它看成第一本入门教程。它更适合放在做过几个原型之后，用来把零散经验整理成可复用的设计判断。

## 适合谁

- 已经做过 Agent 原型，开始想系统整理常见模式的人
- 想把工具调用、规划、反思、多 Agent 等能力放回架构语境里理解的人
- 不满足于“框架 API 怎么写”，想知道模式为什么成立、边界在哪里的人

## 不太适合谁

- 现在还没跑通最小工具调用或最小工作流的人
- 只想找一份按步骤复制的项目教程的人
- 还没有真实问题，只想一次性背完所有设计模式的人

## 我为什么把它收进来

- 它补的是本站之前相对缺的一层：不是单个产品拆解，也不是项目教程，而是 Agentic 系统的模式语言
- 它适合和 `AI Agent Book` 对照着看：一个偏模式索引，一个更偏生产化和治理问题
- 它能帮助我把“这个功能看起来很智能”拆回更具体的问题：用了什么模式，解决了什么约束，又引入了什么成本

## 建议怎么用

我会按问题来读，而不是从头平均扫。

更合适的用法是：

1. 先快速浏览目录，把常见 Agentic 模式的名字和边界立起来。
2. 手头正在做工具调用、任务规划、反思修正或多 Agent 协作时，再回到对应章节细读。
3. 每读一个模式，都逼自己写一句反问：这个模式在我的项目里是真的降低复杂度，还是只是在制造架构感。
