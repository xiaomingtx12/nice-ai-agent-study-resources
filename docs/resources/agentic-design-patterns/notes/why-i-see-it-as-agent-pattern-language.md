# 为什么我把它看成 Agent 模式语言补课

我最想从这条资源里拿走的，不是某个模式名字，而是一套能讨论 Agent 设计的语言。

很多 Agent 项目做着做着会变成一锅能力混合物：工具调用、规划、记忆、反思、多 Agent、工作流，全都能加，也全都能说出一点理由。但真正难的是判断：现在这个问题到底需要哪一种能力，它解决的是不确定性、上下文不足、任务拆解，还是执行反馈不稳定。

## 它补的不是入门，而是判断

入门教程通常解决“怎么跑起来”。这很重要，但一旦系统开始变复杂，只知道怎么跑就不够了。

模式语言解决的是另一个问题：当我和别人讨论一个 Agent 系统时，能不能把分歧落到具体模式上，而不是只说“这里要更智能一点”。

比如：

- 这里是需要更好的工具接口，还是需要先把任务规划拆清楚
- 这里是需要模型自我反思，还是需要外部评估和校验
- 这里引入多 Agent 是职责分离，还是把一个简单流程拆得更难调试

这些问题比“用哪个框架”更接近长期能力。

## 我会怎么读它

我不会按“看完所有模式”的方式读。那样很容易只留下术语感。

更合适的读法，是把它当作项目旁边的模式索引：当项目里碰到工具调用不稳、任务拆解混乱、反馈无法闭环、多 Agent 边界不清时，再回头找对应模式。这样读出来的内容会更有抓手。

## 我先记住的判断

- 模式不是越多越好，能不用复杂模式解决的问题就不要复杂化
- 一个模式是否值得引入，要看它有没有降低系统里的关键不确定性
- 读模式手册时，必须同时记录“什么时候不该用它”

## 和其他资源怎么搭配

它可以放在 `AI Agents From Zero` 之后读：先通过项目获得手感，再回来整理模式。

它也适合和 `AI Agent Book` 对照：前者帮我命名常见 Agentic 设计，后者提醒我这些设计进入生产后会遇到预算、安全、观测和治理问题。
