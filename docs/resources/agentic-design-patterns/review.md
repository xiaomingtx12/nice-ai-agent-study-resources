# Agentic Design Patterns 锐评

先说结论：这条资源最适合作为“模式语言补课”，不适合被当成入门教程或万能架构清单。

它的价值在于把 Agent 系统里常见的做法整理成可讨论的模式。真正有用的不是记住每个模式的名字，而是开始能判断：现在这个问题到底需要规划、反思、工具、记忆、多 Agent，还是只需要一个更稳的普通流程。

## 我觉得它最值钱的地方

第一，它能把零散经验整理成结构。很多人做 Agent 原型时会同时接触工具调用、工作流、记忆、规划和多 Agent，但这些东西经常只是堆在一起。模式视角的好处，是让你开始问每一层能力到底在系统里承担什么职责。

第二，它很适合做架构对照。读 `AI Agent Book` 时，你会看到更多生产化、治理和工程边界；读这条资源时，可以先把常见设计模式整理出来，再回头看哪些模式在生产环境里会长出预算、安全、观测和权限问题。

第三，它提醒你别把框架写法误当成长期知识。具体框架会换，但“什么时候需要计划”“什么时候要引入反思”“什么时候多 Agent 只是在制造沟通成本”这些问题更耐用。

## 我保留意见的地方

第一，模式手册很容易被读成模式清单。真正的难点不是知道某个模式存在，而是判断它在具体场景中值不值得上。

第二，如果缺少项目经验，它可能会显得抽象。没有亲手做过几个失败的 Agent 原型，很难真正理解这些模式为什么要被单独拎出来。

第三，Agent 领域变化很快，某些术语和示例会随生态变化而变。更稳妥的读法，是把它当判断框架，而不是当固定答案。

## 值不值得投入时间

如果你已经做过一些 Agent 或 AI 编程项目，它值得读，而且适合穿插在项目中读。

如果你还在补最基础的 API、工具调用和工作流概念，可以先看 `HelloAgents` 或 `AI Agents From Zero`，等有了基本手感再回来。

## 如果时间有限，先从哪部分入手

- 先看能解释“为什么要这样设计”的章节，不要先背术语
- 正在做项目时，优先读和当前问题相关的模式
- 每看完一个模式，都写一句“我会在哪种场景不用它”，这比只写优点更重要
