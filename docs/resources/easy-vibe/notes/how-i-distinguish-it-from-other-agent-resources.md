# 怎么把它和站里其他 Agent 资源区分开来看

- 来源：[https://datawhalechina.github.io/easy-vibe/zh-cn/](https://datawhalechina.github.io/easy-vibe/zh-cn/)
- 参考仓库：[https://github.com/datawhalechina/easy-vibe](https://github.com/datawhalechina/easy-vibe)

## 它和前面几条不是一个问题域

如果只看“AI 编程”“Agent”“课程”这些标签，Easy-Vibe 好像能和站里很多资源放在一起。

但我现在会把它很明确地分开，因为它解决的问题根本不一样。

## 它更关心“怎么把人带进来”

`HelloAgents` 更像地图，帮你建立 Agent 主线。

`AI Agent Book` 更像架构手册，帮你看系统复杂度。

`Learn Claude Code` 和 `CCB` 更像在拆 Claude Code 这类 coding agent 的机制和架构。

`OpenClaw 源码解析` 更像真实大系统的源码导读。

而 `Easy-Vibe` 更关心的是：怎么把一个原本可能不会写程序、或者还没有完整技术栈的人，带进 AI 编程这条路。

## 所以我会怎么用它

如果我要补底层系统认知，我不会先看它。

如果我要研究 AI 编程的学习路径设计、产品 onboarding、非传统开发者怎么进入这件事，它反而会很有参考价值。

换句话说，它的价值不主要在“技术深度”，而在“进入路径设计”。

## 一个实际判断

这条资源最适合和更硬的资料搭配着看。

它负责让人先上路、先看到成果、先形成连续的学习体验；而别的资源再去补架构、运行时、源码和系统治理。

这样看，它就不会显得“太浅”，因为它本来就不是为了替代深度材料而存在的。
