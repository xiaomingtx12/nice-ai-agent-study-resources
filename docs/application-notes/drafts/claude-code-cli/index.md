# Claude Code CLI 架构拆解

这一组是基于 **Claude Code Best v2.8.2**（逆向工程复刻仓库 `claude-code-best/claude-code`，HEAD `d0713bdd`，V5 主线）的 25 篇架构拆解。研究对象是反编译还原后 LLM 行为一致的复刻 CLI，**不是 Anthropic 官方闭源源码**——这一前提决定了所有正文里的 `src/...` 路径都是还原仓库内部模块路径，不能直接点开 Anthropic 官方仓库验证。

## 关于版本与基线

- **仓库**：[claude-code-best/claude-code](https://github.com/claude-code-best/claude-code)
- **HEAD**：`d0713bdd`（git describe: `v2.8.2-9-gd0713bdd`）
- **分支**：V5（项目内编号体系，外部称 v2.8.2）

行号与文件路径以 HEAD 为准。后续版本可能有漂移；以函数名定位为准。正文各篇顶部 `:::info 项目版本与定位` 已重复标出。

## 这一组怎么读

认知路径建议沿"骨架 → 循环 → 上下文 → 扩展 → 协作 → 基础设施"的顺序，但不必逐篇精读——后文按主题分组、按"先建坐标系再进主题"的方法组织，跳读也走得通。补几句经验：

- **`cc-02` 是全景图**。Harness 十二组件清单相当于把后续 24 篇都在一张图里点亮一遍；读完它再去读 `cc-04`（Agent 主循环）会知道循环层在 Harness 里扮演什么角色。
- **核心循环是全书重心**。`cc-04`（主循环）、`cc-05`（流式渲染）、`cc-10`（工具管线）、`cc-14`（权限安全）共享一个主语——`query()` 的 `for await` 循环与它吐出的 `AsyncGenerator<StreamEvent>`；四篇顺序读，把"Agent 怎么想、怎么做、能做什么"一次搞透。
- **上下文与压缩是隐式主线**。`cc-06`（上下文装配）字面上讲 prompt 组装，但它讲的 CLAUDE.md 分层、cache 边界是 `cc-04` 每轮循环的输入；`cc-08`（压缩子系统）则回答长会话怎么不爆 context window。两篇是理解"Agent 记得什么、怎么记、记不下时怎么丢"的关键。

按主题分组的阅读路径：

```
骨架（02）：建立全局坐标
  02（Harness 设计）

循环与渲染（03-05）：Agent 怎么想、怎么做
  03（入口与生命周期）→ 04（主循环）→ 05（流式渲染）

上下文与记忆（06-09）：Agent 看到什么、怎么记
  06（上下文装配）→ 07（附件总线）→ 08（压缩）→ 09（推理与 CoT）

工具与扩展（10-11）：在主循环里加领域能力
  10（工具管线）→ 11（Skill 系统）

集成与安全（13-16）：Agent 与外部世界、HITL 的边界
  13（MCP 集成）→ 14（权限与安全）→ 15（Hook 拦截）→ 16（人在环路）

协作（17-20）：多 Agent 怎么相处
  17（子 Agent 隔离）→ 18（Plan 模式）→ 19（Agent Teams）→ 20（任务管理）

  21（后台任务）→ 22（动态工作流）→ 23（定时任务）

基础设施（24-26）：闭环所需的存储与观测
  24（持久化与缓存）→ 25（可观测性）→ 26（端到端走一遍）
```

## 配套约定

- **图表**：正文用 ASCII art 绘制架构图与状态机，保留 ASCII 原图、未转成 mermaid。ASCII 图在代码块里渲染正常，转换反而破坏原图的密集标注。
- **文章结构**：每篇开头有"配套阅读"标注与"文章结构表"，便于定位核心章节。
- **路径引用**：`src/path/file.ts:line` 是行号锚点的标准写法，可在还原仓库里 `git grep` 反查。

## 配套阅读边界

这套文档刻意**只讲实现机制、不讲使用**。想学 `/skill` 命令怎么触发，去看 [claude-code-best 官方文档](https://ccb.agent-aura.top/)；想看用户视角的 UI 截图与命令示例，同上。这套文档里出现的命令、参数、UI 元素都是"代码里那个变量、那个函数"的指路牌，不是用法手册。
