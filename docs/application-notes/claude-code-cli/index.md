# Claude Code CLI 架构拆解

这一组是基于 Claude Code CLI（Anthropic 官方命令行工具）做的架构拆解，共 18 篇，沿“先理解生命周期，再深入核心循环，然后看上下文与扩展”的认知路径组织，覆盖分层架构、入口生命周期、Agent 主循环、流式渲染、工具管线、权限安全、上下文装配与压缩、Skill 系统、子 Agent 隔离、Plan 模式、Hook 拦截、人在环路、定时任务、MCP 集成、Worktree 隔离、持久化与可观测性。

## 关于源码引用

Claude Code 是 Anthropic 的闭源商业 CLI，没有公开仓库可指。因此正文里的 `src/...` 路径是逆向工程恢复出来的内部模块路径，作用是让读者知道“这个机制落在哪个模块、哪一行”，但不能点开验证。读这一组要接受这个前提：证据链是逆向工程的产物，不是官方文档；如果与 Anthropic 后续的官方披露或 CLI 行为有出入，以实际行为为准。

## 这一组怎么读

认知路径已经很有条理，沿用它即可。补三句经验：

- **先建坐标系再进主题**。`cc-01`（六层架构总览）是全景图，读完拿到“七层分层 + 循环层是唯一中枢”的坐标，再挑关心的主题深入，事半功倍。
- **核心循环是全书重心**。`cc-03`（Agent 主循环）和 `cc-04`（流式渲染）共享一个主语——`query()` 的 `while(true)` 与它吐出的 `AsyncGenerator<StreamEvent>`；`cc-05`（工具管线）和 `cc-06`（权限安全）则共同回答“Agent 能做什么、不能做什么”。四篇顺序读。
- **上下文与压缩是隐式主线**。`cc-07`（上下文装配）字面上讲 prompt 组装，但它讲的 CLAUDE.md 分层、System Prompt 静态/动态段、缓存边界是 `cc-03` 每轮循环的输入；`cc-08`（压缩子系统）则回答长会话怎么不爆 context window。这两篇是理解“Agent 记得什么”的关键。

按主题分组的阅读路径：

```
入门（01-02）：建立全局坐标与生命周期观
  01（六层总览）→ 02（入口与生命周期）

核心循环（03-06）：Agent 怎么想、怎么做、能做什么
  03（主循环）→ 04（流式渲染）→ 05（工具管线）→ 06（权限安全）

上下文与记忆（07-08）：Agent 记得什么
  07（上下文装配）→ 08（压缩子系统）

扩展能力（09-11）：在主循环里加领域知识、并行分支、工作模式
  09（Skill 系统）→ 10（子 Agent 隔离）→ 11（Plan 模式）

协作与集成（12-15）：Agent 怎么和外部世界交互
  12（Hook 拦截）→ 13（人在环路）→ 14（定时任务）→ 15（MCP 集成）

基础设施（16-18）：Agent 运行的支撑系统
  16（Worktree 隔离）→ 17（持久化与缓存）→ 18（可观测性）
```

## 配套约定

- **图表**：正文用 ASCII art 绘制架构图与状态机，保留 ASCII 原图、未转成 mermaid——ASCII 图在代码块里渲染正常，转换反而会破坏原图的密集标注。
- **文章结构**：每篇开头有“配套阅读”标注与“文章结构表”，便于定位核心章节。
