# 工程化源码解析

本栏以单个项目为主语，选择其中有代表性的工程问题深入源码。项目可以是 Agent 框架、开发平台、完整应用或配套基础设施；收录依据是具体实现价值和可核验证据。

一组解析不要求覆盖项目全貌。Dify 可以只深挖应用配置和工作流执行，Coze Studio 可以先研究编辑对象怎样发布为运行版本，AgentScope 可以先追 Agent 循环与人工确认。其他模块在产生明确问题后再补。

## 项目类型只是索引

## 新项目先写项目卡，再决定篇数

项目卡放在系列入口页顶部，至少记录以下信息：

| 字段 | 作用 |
| --- | --- |
| 研究对象 | 写清项目、仓库、版本或 commit，以及是否涉及外部依赖 |
| 代表问题 | 说明本次为什么读它，例如“编辑中的工作流怎样成为稳定运行版本” |
| 关键链路 | 列出入口、核心状态、执行组件和结果出口 |
| 验证范围 | 区分源码静态阅读、测试断言、本地运行和线上产品观察 |
| 排除范围 | 明确本轮不讨论的模块，防止系列失控 |
| 预期判断 | 计划回答哪些值得照搬、需要改造或不适用的问题 |

项目卡通过后，按调用链和问题复杂度决定是一篇还是一个系列，不预设固定篇数。只有 README 能回答的内容放在资源导航；需要追代码行为、约束和代价的内容才进入本栏。

## 建议的下一批单项目解析

1. **AgentScope 执行主线**：为 AgentScope × Deep Agents 对比建立同等深度的源码基线。
2. **Coze Studio 对象与发布主线**：先确认 Agent、App、Workflow、Plugin、Knowledge 等对象的关系，再追编辑、发布和运行。
3. **Coze Loop 数据闭环**：追一次运行记录怎样进入 Trace、评测集、实验和结果比较。
4. **OpenHands 软件 Agent 主线**：固定 Software Agent SDK 或具体应用仓库，研究任务、工作区、命令执行和结果交付。

这四条主线分别为框架、平台、质量基础设施和完整应用提供基线，后续横向对比可以引用已经核验的调用链，减少重复源码说明。
