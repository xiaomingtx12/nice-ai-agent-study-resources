# 产品业务

这里关注谁在什么场景下使用产品、怎样完成任务、结果由谁验收，以及使用和交付成本是否合理。可以写单个产品，也可以比较同一任务下的不同产品；开源与商业产品均可作为研究对象，需写清版本和可观察范围。

> 当前为栏目组织与选题规划，具体案例待开展。下文中的产品配对和文章标题均为候选选题。

首批共同任务、候选产品和文章顺序见[产品案例路线图](./roadmap.md)。

## 按用户任务分组

主目录按使用场景组织。交互、商业模式、增长与留存是分析角度，放进具体案例中；一个案例不需要机械覆盖全部角度。

| 计划目录 | 主要用户任务 | 可研究的问题 |
| --- | --- | --- |
| `app-building/`：应用构建与交付 | 搭建、调试、发布并维护 AI 应用 | 首次可用需要多少准备？配置错误怎样被发现？交付后谁继续维护？ |
| `software-development/`：软件开发与协作 | 理解代码、修改、验证、审查和交付 | 怎样表达任务？怎样确认变更？失败后怎样接管？ |
| `knowledge-work/`：知识工作与研究 | 搜集资料、组织知识、研究和产出文档 | 证据能否追溯？知识如何更新？用户怎样判断结果可信？ |
| `business-operations/`：业务流程与运营 | 处理客服、销售、内容运营等业务任务 | AI 接管哪一步？怎样移交给人？是否降低整个流程的成本？ |
| `agent-quality/`：Agent 调试与质量运营 | 定位失败、维护评测集、判断版本能否交付 | 开发、测试与运营怎样协作？一次问题怎样进入回归检查？ |

这些目录在首篇内容落地时创建。业务运营积累足够多案例后，再按客服、销售等具体场景拆分。一个产品有多种用途时，文章按本次研究的用户任务归属，其他入口通过链接引用。

## 每个案例选择要回答的问题

| 分析角度 | 具体问题 | 需要的证据 |
| --- | --- | --- |
| 用户与任务 | 谁使用、谁采购、谁维护？原来怎样完成任务？ | 使用流程、访谈、公开案例；未直接验证的用户描述需注明来源 |
| 关键交互 | 用户怎样输入目标、补充信息、修改过程和接管失败？ | 同一任务的操作记录、界面状态、错误与恢复过程 |
| 结果交付 | 交付的是回答、文件、代码变更还是业务动作？谁验收？ | 真实产物、验收标准与下游使用步骤 |
| 业务效果 | 节省了哪部分工作，增加了哪些审核和维护工作？ | 任务成功率、耗时、人工介入次数、返工成本及样本条件 |
| 商业与采用条件 | 收费对象与计费单位是什么？接入、运维和迁移成本由谁承担？ | 对应日期与版本的公开定价、文档、合同或可核验案例 |

公开价格不能证明收入和利润，开源热度不能证明用户留存。缺少真实业务数据时，文章可以给出产品机制分析和待验证假设，不补写经营结论。

## 同一产品怎样分出工程与产品文章

以 Coze Studio 与 Dify 的同场景研究为例，两篇文章可以共享任务设定，分别回答不同问题：

| 去向 | 候选题目 | 正文重点 |
| --- | --- | --- |
| 工程化 | Coze Studio 的工作流配置如何进入执行链路 | 一个项目的对象、调用、状态变化和边界 |
| 工程对比 | Coze Studio × Dify：编辑态与运行态怎样衔接 | 两种实现的版本引用、执行责任和变更代价 |
| 产品业务 / 应用构建 | 用同一份资料交付问答助手，需要哪些操作与人工判断？ | 两条用户路径、调试反馈、发布体验和维护负担 |

产品比较要固定用户目标、输入资料、模型配置、产品版本和任务完成标准，记录无法对齐的条件。若使用商业在线版，结论只针对该版；开源仓库中的实现不能直接证明在线产品行为。

[Coze Studio 官方说明](https://github.com/coze-dev/coze-studio)明确区分开源版与商业版功能。[Coze Loop](https://github.com/coze-dev/coze-loop)的提示词、评测与观测方向，可放入 Agent 调试与质量运营场景；其工程实现另在工程化或工程对比中展开。资料核对日期：2026-09-21。

## 文章与目录按内容规模增长

单篇案例先放在场景目录下；同一产品形成连续分析后，再建立产品子目录。同场景比较与单产品案例放在一起，避免另建一套覆盖所有场景的“产品对比”目录。

例如，应用构建方向可以先写一篇 Coze Studio 用户路径分析，再增加同任务下 Coze Studio 与 Dify 的比较；每篇只保留一次正文，通过场景索引关联。具体交互需要工程机制解释时，引用对应源码解析；跨案例反复成立的判断再沉淀到「方法与复盘」。
