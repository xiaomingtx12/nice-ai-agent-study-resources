# 产品业务

这里关注谁在什么场景下使用产品、怎样完成任务、结果由谁验收，以及使用和交付成本是否合理。可以写单个产品，也可以比较同一任务下的不同产品；开源与商业产品均可作为研究对象，需写清版本和可观察范围。

现有[LangChain 系列博客案例](./blog-cases/index.md)来自 2026 年发表的 LangChain 公开文章。

## 已沉淀的博客案例

这组案例从具体任务出发，分析执行边界和验收方式。LangChain 系列文章在[案例目录](./blog-cases/index.md)下按六类业务任务组织，覆盖客户服务与服务导航、销售与营销、数据分析与研究、知识工作与协作、软件开发与运维、文档审查与处理。客户叙述与可核对的开源实现分别标明；没有公开生产源码的部分不当作源码解析。案例来源和日期以各篇文章的来源说明为准。

## 按用户任务分组

现有[LangChain 系列博客案例](./blog-cases/index.md)按主要业务任务归类，服务对象、行业和架构方式作为辅助索引；后续产品案例也可以按使用场景组织。交互、商业模式、增长与留存是分析角度，放进具体案例中；一个案例不需要机械覆盖全部角度。

| 计划目录                                  | 主要用户任务                     | 可研究的问题                                                 |
| ----------------------------------------- | -------------------------------- | ------------------------------------------------------------ |
| `app-building/`：应用构建与交付         | 搭建、调试、发布并维护 AI 应用   | 首次可用需要多少准备？配置错误怎样被发现？交付后谁继续维护？ |
| `software-development/`：软件开发与协作 | 理解代码、修改、验证、审查和交付 | 怎样表达任务？怎样确认变更？失败后怎样接管？                 |

## 每个案例选择要回答的问题

| 分析角度       | 具体问题                                                 | 需要的证据                                               |
| -------------- | -------------------------------------------------------- | -------------------------------------------------------- |
| 用户与任务     | 谁使用、谁采购、谁维护？原来怎样完成任务？               | 使用流程、访谈、公开案例；未直接验证的用户描述需注明来源 |
| 关键交互       | 用户怎样输入目标、补充信息、修改过程和接管失败？         | 同一任务的操作记录、界面状态、错误与恢复过程             |
| 结果交付       | 交付的是回答、文件、代码变更还是业务动作？谁验收？       | 真实产物、验收标准与下游使用步骤                         |
| 业务效果       | 节省了哪部分工作，增加了哪些审核和维护工作？             | 任务成功率、耗时、人工介入次数、返工成本及样本条件       |
| 商业与采用条件 | 收费对象与计费单位是什么？接入、运维和迁移成本由谁承担？ | 对应日期与版本的公开定价、文档、合同或可核验案例         |

公开价格不能证明收入和利润，开源热度不能证明用户留存。缺少真实业务数据时，文章可以给出产品机制分析和待验证假设，不补写经营结论。

## 文章与目录按内容规模增长

LangChain 系列博客文章归入博客案例目录中对应的业务任务子目录；其他来源的单篇案例先放产品业务目录，形成足够多同场景文章后再建立场景目录。同一产品形成连续分析后，再考虑产品子目录。
