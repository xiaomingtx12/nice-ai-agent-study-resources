# 关于我

你好，我是这个站点的维护者。

学了看了很多东西发现很容易忘记，之前有做整理记录但是较为分散，基于此，搭建这个仓库，从学习AI作为契机，进行记录整理。

站点整体的构建都是站在巨人的肩膀上，能想到的点，往GitHub上一查，总是能发现已经有对应实现。

关于站点构建意义的想法：方便更高效的去激活AI模型里面的知识内容，模型会持续进化，越来越聪明，知识量掌握的量也越多，比人去理解的快速，但是具体去驾驭，人应该不断去提升判断，提升人机协作的能力。

站点构建维护过程中，发现搞出来一些没用废话的内容放上去也非常丢人，慢慢搞吧，希望能持续进化沉淀出高价值的内容。

## 一、课外学习与实践经历回顾

这里只记录学校课程之外的学习、部门实践、实习和求职经历。学年划分沿用原有回顾；各门课的时间与完成程度来自回忆，不等于相关技术都已熟练掌握。2026 年 10 月 31 日的补充叙述及讨论另见[学习经历复盘对话记录](./learning-review-dialogue.md)。

### 1、前端起步

#### 大一（2022年~2023年）

刚入学时没有编程基础，先上网了解前端和后端。当时听到的建议是：后端可能更看重算法，结合双非本科背景，前端更适合作为就业方向。前端入门直观，页面做好后马上有反馈，这也吸引了我。这些是当时影响我选择的说法，不等于学历决定了适合什么方向，也不等于前端无需算法。

先看 B 站黑马 pink 老师的[前端入门课程](https://www.bilibili.com/video/BV14J4114768/)，这门课没有 JavaScript，主要学 HTML、CSS 和页面布局；还参考过 [arryblog 前端教程](https://www.arryblog.com/)。大一下加入学校的前端技术部门，使用 Bootstrap 按设计图还原响应式页面，同时读过张鑫旭的《CSS 世界》。

后来通过同学分享的网盘课程资料接触 coderwhy 的前端体系课，花较长时间学 JavaScript 基础、DOM、BOM、V8 引擎、闭包、作用域等，也接触打包工具、Node.js 基础、Vue、React 和小程序。读过阮一峰的 ES6 教程、《你不知道的 JavaScript》和《JavaScript 高级程序设计》。当时已经有页面任务，却还不太会从一个完整应用出发决定学什么；面对语言和 CSS 的诸多细节，感觉总有内容需要继续补。

#### 大二上（2023年~2024年）

继续学习前端。按原有回顾，这时担任部门部长，负责页面开发和新部员技术培训，开始思考如何拆解页面、把技术讲清楚。具体交付与培训效果尚未展开，不能把这一阶段简单概括为“只看课程”。

### 2、后端扩展与全栈项目

#### 大二到大三（2023年~2025年，转向 Java 的起始时间待核对）

当时在掘金、公众号频繁看到“前端已死”的讨论，担心就业，逐渐把重心转向 Java。原版回顾记为大二下到大三，这次口述只明确“大二上仍在学前端”，暂不写死转向的月份。原版还提及尝试过 Node.js、three.js。

沿着黑马课程学习 Java 基础、JavaWeb、SSM、Spring Boot，以及苍穹外卖、点评项目。做这些课程项目后开始建立完整应用的意识，但学习内容仍主要由下一门课程决定。随后通过[犬小哈教程](https://www.quanxiaoha.com)接触单体前后端分离博客、社区项目：前端练习组件、打包、状态管理和路由；后端接触 Maven 分模块、日志系统、全局异常处理。再往后接触微服务项目的注册中心、网关等组件。

还学习过鱼皮的智能协同云图库项目，尝试调用模型接口；在接触 Spring AI 1.0 时做过简单的 RAG 实践。这里的 RAG 指检索资料并提供给模型辅助回答。开始把前后端和 AI 能力放进同一个应用来理解。

### 3、全栈开发实习

#### 大三下暑假（2025年6月~9月）

参与全栈开发实习，原有回顾记录的技术栈是 Java、Vue、Uniapp。开始按照实际需求开发功能，经验不足时需要请教前辈，也逐步了解团队协作和工程交付。尚未补充具体负责的需求、独立完成的部分、上线结果和遇到的故障。

### 4、AI 应用与秋招选择

#### 实习之后，大四上（2025年下半年）

继续学习消息队列（MQ）等中间件原理，并配合慕课网实战课、极客时间专栏学习 Java 并发工具与机制（JUC）、Java 虚拟机（JVM）。当时在关注中间件实现和产品动向时，注意到 RocketMQ、网关和 Nacos 注册中心陆续扩展面向 AI 场景的能力；印象较深的是 RocketMQ 推出的 LiteTopic。这让 AI 应用不再只是调用模型接口的新方向，也成为能与已有后端工程知识衔接的系统问题，促使我进一步了解它。随后接触极客时间 AI 全栈开发训练营，对 AI 应用的认识主要围绕提示词和上下文，也用 Dify、FastGPT 搭建过应用。

现在回看，我认为这些中间件能力可以支撑 Agent 在云端长期运行的部分需求，例如任务消息传递、服务接入与发现。但 Durable Agent 还需要持久化执行状态、失败恢复、重试与幂等等机制，不能仅由 LiteTopic、网关或注册中心的 AI 扩展推导出完整的可恢复执行能力。上述产品变化先按当时的观察记录，具体功能与发布时间未在这里核验。

2025 年 9 月秋招期间，感觉自己技术还不够好：算法不会，框架和中间件原理也不扎实。尝试学算法，理解得不太顺利，最后没有投递，选择继续学技术。当时没有用投递和面试反馈校准能力，这是需要重点复盘的决定。

之后关注 LangChain、LangGraph 和 Agent 开发，觉得这也许是新机会。学习实践 Flask + Vue + LangChain 0.x 的 LLMOPS 全栈 AI 应用课程项目。通过 LCEL（LangChain 的组件组合表达方式）理解链式应用，通过 LangGraph 接触带状态、分支与循环的流程。当时将两者概括为“LangChain 线性、LangGraph 非线性”，现在看只是阶段性的简化认识，不能作为框架能力的完整边界。

### 5、春招与毕业

#### 大四下到毕业（2026年上半年）

参加春招，进入过一些中大厂面试，有的技术面可以通过；面试经验不足，也会紧张。最终拿到北京一家中小厂的 offer。面试时被问到 LangChain 系列框架原理和 AI 应用高并发；面对后一个问题有些意外。模型调用通常有较长的 I/O 等待，异步处理是可能的设计方向之一，但还要结合限流、队列、超时、并发上限等具体瓶颈判断。之前学过 NIO、Netty，当时没能把已有知识迁移到这一场景。

2026 年 6 月毕业后回家继续学习，仍感到技术能力不足。本次叙述没有交代 offer 条件、是否入职或拒绝、经济和家庭约束，暂不能断言这一选择正确或错误。

### 6、阅读开源与探索 Agent 平台

#### 毕业之后（2026年6月至本次回顾）

开始利用 AI 辅助阅读 Dify 等开源项目，发现之前做的 LLMOPS 课程项目在能力和组织方式上与 Dify 有许多相似之处，形成“LangChain 版 Dify”的个人理解；是否存在直接借鉴关系，仍需项目来源和代码证据。探索过 LLMOPS 的 MCP 工具扩展，也关注 LangChain 生态的相关适配。MCP 是连接模型应用与外部工具、资源的协议。

随着 Skill 受到关注，希望把可复用的任务说明与资源整合进 Agent 平台；阅读 DeerFlow 2.0，接触其机制。随后关注 Deep Agents、AgentScope 等 Harness 框架，尝试基于现成框架重构平台，再阅读 Octop 的实现。这里 Harness 指围绕模型提供工具、上下文、状态和运行控制的配套机制；各开源项目的具体架构和版本关系仍需单独核验。

接下来希望补强云端长程运行能力，建设具备持久化、故障恢复能力的 Durable Agent。目前没有记录已交付范围、长时间运行或故障恢复的验证结果，因此先写成正在探索的目标。

## 二、这次复盘提出的问题

旧版回顾用“学者思维”“战术上的勤奋掩盖思维上的懒惰”评价这段经历，容易把可以调整的行为变成对整个人的判断。当前更值得追问的是：

- 课程和书籍长期主导学习顺序；独立定义任务、做取舍、交付和验证的次数是否偏少？部门开发、培训和实习又提供了哪些反例？
- 从前端到 Java、再到 AI，哪些转向是兴趣和能力的自然延伸，哪些受行业舆论影响？转向本身不是错误，但需要核算切换成本。
- 2025 年秋招不投递带来了什么机会成本？当时是否把“准备好”设为接收市场反馈的前提？
- 春招获得面试和 offer 后，为什么仍主要用“技术太菜”解释处境？需要拆成具体能力差距，而非否定全部进展。
- 看过 NIO、Netty，却在面试中未联系到模型调用的 I/O 等待，是否缺少知识迁移练习？紧张因素有多大？
- 现在阅读源码、重构平台的过程，有哪些独立交付、真实用户和运行指标？否则可能继续以输入量替代成果验证。
