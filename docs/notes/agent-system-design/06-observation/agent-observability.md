# 证据与反馈

## 本质问题

最终结果只能告诉我们任务表面上成功或失败，不能说明哪一次决策、哪个工具、哪条上下文或哪项权限造成了问题。证据层要让 Agent 的行为可以解释、回放和改进。

## 观察对象

至少记录以下边界：

```text
task
  → decision
  → model call
  → tool/action
  → observation
  → state transition
  → termination
```

每个运行需要稳定的 `trace_id`、`run_id`、`span_id`、版本和租户信息。

## 记录什么

记录摘要和结构化字段，不默认保存全部敏感内容：

- 输入和输出摘要；
- 当前状态版本；
- ContextView 版本和 token；
- 模型、Provider 和 usage；
- 动作名称、参数摘要和结果类型；
- 权限、审批和 Postcondition；
- 重试、恢复和退出原因；
- 延迟、成本和资源消耗。

凭据、完整文件内容和敏感用户文本必须有脱敏、访问和保留策略。

## 最小实现

1. 先定义 Trace、Span、Event 的父子关系。
2. 在模型、Context、Tool、文件、审批、Checkpoint 和子 Agent 边界埋点。
3. 为错误、取消、拒绝、部分成功和恢复建立稳定事件类型。
4. 将高成本或高敏感内容异步写入，前台只等待必要确认。
5. 保留足够信息重建决策，不要求永远保存全部 Prompt。

## 评测回流

评测不是只给最终答案打分，而应分层：

| 层级 | 评价什么 |
|---|---|
| 任务级 | 是否达到成功条件 |
| 决策级 | 路由、计划、重排是否合理 |
| 动作级 | Tool 参数、权限、幂等和结果处理 |
| 状态级 | 恢复、版本和副作用是否正确 |

每个失败结果必须能够回到一个可修改的上游合同，例如任务合同、ContextView、能力 Schema、治理规则或生命周期策略。

## 失败模式与验收

| 失败行为 | 保护方式 |
|---|---|
| 只记录最终回复 | 保存状态转移和动作链 |
| Trace 没有父子关系 | 统一运行身份和 Span 语义 |
| 日志包含凭据和完整文件 | 脱敏、采样和保留期 |
| LLM 自评直接当结论 | 规则、人工和多次回放校准 |
| 只看平均延迟 | 观察尾延迟和队列等待 |
| 评测结果不改系统 | 明确指标到组件的回流路径 |

## 相邻边界

- 生命周期保存恢复事实，证据层记录恢复过程。
- 评测判断质量，不负责修改 Prompt 或 Tool。
- 治理层决定动作是否允许，证据层记录决定过程。
