# Agent 评测

## 本质问题

Agent 不一定每次走同一条路径，但每次都必须满足任务合同、安全边界和可接受的终态。评测要回答“哪里错、为什么错、改动是否真的变好”，而不只是给最终文本打分。

## 触发条件

只要任务包含多轮决策、工具副作用、恢复或多个 Agent，就应建立最小评测闭环。没有稳定成功标准、无法重建外部依赖时，先补任务合同和 Trace，不要急着造总分。

## 输入、输出与状态

```text
task contract + replayable trace + oracle
        → rule / program / model / human judges
        → verdict + failure attribution + regression case
```

- `TaskContract`：目标、约束、成功条件和拒答条件。
- `Trace`：模型输入、决策、动作、结果、状态转移和退出原因。
- `Oracle`：终态、必须经过的安全门、允许的替代路径和关键事实。
- `Verdict`：通过、失败、风险、成本和可定位的上游组件。

## 评测粒度

| 层级 | 判断什么 | 典型检查 |
|---|---|---|
| 任务级 | 是否达到业务终态 | 成功条件、交付物、拒答是否正确 |
| 决策级 | 路由和计划是否合理 | 选择、重排、停止和追问 |
| 动作级 | 执行是否符合合同 | 工具名、参数、权限、幂等 |
| 状态级 | 是否可恢复且无重复副作用 | Checkpoint、事件顺序、最终状态 |

## 最小实现

1. 从真实任务抽取小而分层的评估集，固定输入、模型配置、工具版本和外部数据快照。
2. 先用规则和程序检查结构、安全、参数、步数和终态，再用模型或人工判断语义质量。
3. 每个失败都映射到一个可修改的合同：Goal、View、Decision、Action、State 或 Harness。
4. 线上事故直接转成回归样本；版本变更先跑离线回归，再做影子或小流量验证。
5. 正确性、风险、成本和尾延迟分开报告，不能用便宜或快速替代正确。

## 失败出口与验收

评测器本身无法判定时输出“不确定”，转人工校准；外部依赖版本漂移时标记样本失效，不把环境噪声算成模型退化。

验收至少覆盖：正常任务、缺参数、工具失败、重复执行、权限拒绝、用户取消、部分成功、终态校验失败和多 Agent 结果冲突。

## 相邻边界

- [证据与反馈](./agent-observability.md)负责产生可回放事实，本篇负责判定和回流。
- RAG 评测只深入知识视图的证据质量，不替代端到端 Agent 评测。
- [权限、审批与结果验收](../05-action/agent-permission-and-postconditions.md)定义运行时硬门，评测验证这些硬门是否生效。
