# 上下文装配：为每轮模型调用编译输入

> 上下文装配的核心本质，是从任务当前可获得的全部信息中，选择本轮模型完成决策所需的最小充分集合，并按阶段、优先级、预算、权限和时效组织成可解释的输入。

模型每次调用都面对有限输入窗口。缺少关键事实会导致猜测，无关信息会分散注意力，过期内容会让模型基于错误依据继续工作。上下文装配把这些风险转化为一条确定的输入处理流程：

```text
收集来源
→ 筛选内容
→ 排定优先级
→ 分配预算
→ 渲染输入
→ 校验可见内容
```

## 一、模型需要什么输入

一次模型调用通常需要五类材料：

| 材料 | 作用 | 变化方式 |
|---|---|---|
| 稳定规则 | 身份、输出要求、运行约束 | 版本化管理，变化较少 |
| 当前任务 | 目标、参数、约束、成功条件 | 随任务推进变化 |
| 当前事实 | 已确认结果、进度和待处理事项 | 随运行持续更新 |
| 相关证据 | 文件片段、知识内容、外部查询结果 | 按当前问题动态选择 |
| 可用能力 | 工具、操作说明和结果格式 | 按阶段和权限变化 |

本轮输入可以抽象为：

```text
ContextView =
  stable_rules
  + current_task
  + current_facts
  + selected_evidence
  + available_capabilities
```

记忆、RAG、Skill、文件和外部查询都是输入来源。它们进入模型输入前，都要经过相同的选择、排序和预算处理。

### 模型实际收到的上下文

从模型 API 的角度看，一次请求通常由两部分组成：

| 部分 | 承载内容 |
|---|---|
| 消息序列 | 系统规则、用户任务、模型历史决策和工具结果 |
| 能力定义 | 当前可用工具的名称、用途、输入 Schema 和限制 |

消息序列中的工具调用和工具结果需要成组保留，并通过调用 ID 关联。裁剪历史时不能只保留工具结果而删除对应的模型调用，也不能把一次并行调用拆成无法对应的几条结果。

能力定义位于消息序列之外，但同样属于模型本轮可见输入。工具描述发生变化、权限发生变化或当前阶段发生变化时，能力定义需要重新筛选和装配。

模型 API 通常是无状态的。下一轮调用不会自动记住上一轮内容，运行时必须根据当前状态、历史决策、动作结果和能力范围重新构建请求。上下文装配因此不是一次性拼接，而是每轮都要执行的编译过程。

### 上下文溢出和上下文腐化

上下文问题有两种表现：

- **溢出**：输入超过模型窗口或预算，调用无法完成；
- **腐化**：输入仍然装得下，但无关历史、重复证据和过期内容分散了注意力，模型找不到真正需要的信息。

压缩只在溢出时触发，会错过腐化已经影响决策的时机。阶段切换、重复错误、关键事实被多次覆盖或模型开始重复询问时，也应重新装配或提前压缩。

## 二、上下文装配流程

### 1. 收集来源

先读取当前任务、已确认事实和运行阶段，再按需要获取证据与能力描述：

```text
任务目标
→ 当前阶段
→ 已确认事实
→ 相关证据
→ 阶段可用能力
```

来源读取需要绑定当前任务和阶段，避免把所有历史、所有工具和所有知识一次性加载。

### 2. 筛选内容

每段内容进入本轮前，至少检查：

- 与当前目标的相关性；
- 是否适用于当前阶段；
- 是否仍然有效；
- 当前运行是否有权访问；
- 是否已经重复出现。

相关度高但已经过期或超出权限范围的内容直接排除。

### 3. 排定优先级

模型输入优先保留：

```text
任务约束
→ 已确认事实
→ 当前步骤
→ 验收条件
→ 直接证据
→ 补充背景
```

排序让模型先获得任务边界和当前事实，再读取扩展材料。

### 4. 渲染输入

不同材料使用稳定区域和标签，保持来源边界：

```text
<rules>...</rules>
<task>...</task>
<facts>...</facts>
<evidence>...</evidence>
<capabilities>...</capabilities>
```

动态内容在固定区域内更新，便于模型理解、缓存和回归。来源、版本和选择理由由系统保留，按需要决定是否展示给模型。

### 5. 校验可见内容

模型调用前检查：

- 必需字段是否齐全；
- 过期和越权内容是否已移除；
- 当前阶段是否暴露了不必要的能力；
- 预算是否足够；
- 每段动态材料是否可以追溯来源。

## 三、阶段可见性

同一个任务在不同阶段需要不同输入：

| 阶段 | 重点内容 | 输入控制 |
|---|---|---|
| 规划 | 目标、约束、相关事实、候选路径 | 提供决策信息，收窄执行能力 |
| 执行 | 当前步骤、参数、必要证据、能力说明 | 聚焦当前动作，减少无关历史 |
| 验证 | 预期结果、真实结果、验收条件 | 提供可比较的事实和判定标准 |
| 修复 | 失败原因、剩余目标、可行修复信息 | 保留失败证据，移除已证伪路径 |

阶段变化后重新装配输入和能力范围，避免一份固定输入贯穿整个任务。

## 四、能力视图：工具如何进入上下文

工具同时存在于 View 和 Action 两个边界中：

- View 暴露当前模型可以使用的能力说明；
- Decision 根据说明提出工具调用；
- Action 校验并执行真实工具；
- Observation 把执行结果返回给下一轮。

进入 View 的是工具描述，不是执行句柄。模型可以看到：

| 工具描述 | 作用 |
|---|---|
| 名称和用途 | 帮助模型判断是否相关 |
| 输入 Schema | 约束模型生成调用参数 |
| 输出和错误格式 | 让模型知道如何消费结果 |
| 使用限制 | 说明阶段、权限、风险和调用条件 |
| 成本和时效 | 帮助模型在多个能力之间取舍 |

凭据、数据库连接、文件句柄和租户上下文留在运行时执行边界内，不能进入模型输入。

工具描述也适合渐进式披露：

```text
工具目录
→ 当前任务相关工具摘要
→ 入选工具的 Schema
→ 分支需要时加载详细说明
→ 模型提出调用
```

能力筛选至少结合任务目标、当前阶段、权限范围、风险等级、预算和工具可用性。所有工具常驻会增加输入成本，也会让模型在相似能力之间更容易选错。

Skill 和工具在能力视图中可以同时出现：Skill 提供完成一类任务的方法，工具提供可以执行的操作。Skill 可以引用工具的使用顺序和验收方式，但不能替代工具的参数校验、权限检查和执行结果。

能力视图的验收重点是：模型只看到当前阶段允许使用的工具，工具描述和真实执行能力保持一致，工具版本或权限变化后相关缓存能够失效。

## 五、预算、取舍与缓存

### 预算分配

```text
总窗口
− 稳定规则
− 当前任务和事实
− 能力描述
− 输出预留
= 动态材料预算
```

动态预算再分配给证据、历史和补充背景：

```text
保留任务约束
→ 保留已确认事实
→ 保留当前步骤
→ 保留必要证据
→ 释放补充背景
```

裁剪、摘要、外部化和重新获取都属于预算策略。每次释放都要记录释放对象、释放原因和重新获取方式。

### 缓存类型

| 缓存类型 | 主要作用 |
|---|---|
| Provider Prompt Cache | 缓存稳定输入前缀，降低重复输入成本 |
| `ContextView` 缓存 | 缓存已经渲染的本轮输入，减少重复装配 |
| 模型响应缓存 | 复用确定性场景下的模型输出 |
| KV Cache | 加速模型当前推理过程 |

Prompt Cache 适合保存稳定规则、固定输出协议和稳定能力描述。任务目标、动态事实、临时证据和阶段能力放在可变化区域。

缓存键至少考虑：

```text
prompt_version
state_version
stage
tool_schema_version
permission_scope
evidence_version
```

规则、事实、阶段、工具权限或证据版本发生变化后，相关缓存需要失效。缓存保存装配结果，失效后根据当前有效信息重新生成输入。

## 六、来源、时效与可见性

动态材料至少保留：

```text
source_id
version
freshness
permission_scope
selected_reason
```

这些字段支持三类判断：

- 内容从哪里来；
- 内容是否仍然有效；
- 内容为什么进入本轮。

系统保留完整元数据，模型只接收当前决策需要的部分。来源不明、已经过期、超出权限范围或无法解释选择原因的内容，不进入当前输入。

## 七、常见装配失败

| 失败现象 | 主要原因 | 调整方式 |
|---|---|---|
| 全量拼接历史 | 缺少任务和阶段筛选 | 按目标、阶段和优先级选择 |
| 动态内容覆盖规则 | 稳定区和动态区混用 | 固定规则区域，动态内容独立注入 |
| 所有工具常驻 | 能力可见范围过大 | 按阶段和权限注入 |
| 过期证据继续使用 | 缺少版本和时效判断 | 记录版本，失效后重新获取 |
| 超预算直接截断 | 没有明确释放顺序 | 按优先级裁剪、摘要或外部化 |
| 阶段内容泄漏 | 一份输入贯穿全流程 | 每次阶段变化后重新装配 |

## 八、上下文装配的验收

### 信息充分性

移除无关背景后，模型仍能获得完成任务所需的事实、约束和证据。

### 信息隔离

不属于当前任务、权限或阶段的内容不会进入输入。

### 阶段一致性

不同阶段的模型调用只看到对应阶段需要的材料和能力。

### 预算稳定性

输入长度、输出预留和动态材料数量处于预期范围，超预算时按既定策略释放内容。

建议跟踪：

```text
关键事实遗漏率
无关内容比例
输入 Token 使用量
阶段内容泄漏率
过期证据命中率
任务完成率
```

上下文装配的结果，可以用一句话验收：模型每一轮都能看到正确、足够、及时且可解释的信息。
