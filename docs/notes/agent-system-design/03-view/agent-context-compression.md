# 上下文压缩：控制输入规模与信息密度

> **模块本质：** 按后续决策的需要减少模型输入，在释放上下文空间时保留关键事实、任务进度和来源，并为被移出的必要细节留下可恢复的路径。

评价一次压缩时，既要看输入减少多少，也要看模型能否继续完成同一项任务。

模型输入会随着多轮对话、工具结果、文件片段和检索证据持续增长。压缩需要回答两个问题：

```text
哪些内容可以从当前输入移除？
移除后，模型如何重新获得必要细节？
```

压缩的目标是降低输入规模，保持模型对任务的正确理解，并控制信息损失。高质量压缩还会把原始材料中需要反复查找、统计或归纳的内容投影成结构化事实，让模型后续可以直接读取结论，同时保留来源以便回溯。

## 一、压缩不只为了解决窗口溢出 {/* #压缩不只为了解决窗口溢出 */}

需要区分两种压力：

- **上下文溢出**：输入超过模型窗口、输出预留或成本预算，调用无法继续；
- **上下文腐化**：输入仍然装得下，但重复历史、无关证据和过期内容分散了注意力，模型找不到真正影响下一步的事实。

因此，压缩可以在输入接近上限时触发，也可以在阶段切换、模型重复询问、相同错误反复出现或关键事实被多次覆盖时提前触发。只等服务端返回超限错误，通常已经错过了降低信息噪声的时机。

## 二、先判断压缩对象 {/* #一先判断压缩对象 */}

不同内容的决策价值和恢复成本不同，压缩顺序应从低风险内容开始：

```text
可直接删除
→ 可以引用替换
→ 可以提炼摘要
→ 必须原样保留
```

| 内容 | 常用策略 | 保留要求 |
|---|---|---|
| 重复规则、重复消息 | 去重或删除 | 保留唯一有效版本 |
| 超长工具结果、搜索结果 | 预览或引用 | 保留结论、来源和重新读取方式 |
| 大文件、长文档 | 分段引用或重新获取 | 保留位置、版本和查询条件 |
| 已结束阶段 | 阶段摘要 | 保留阶段结论、未完成事项和失败假设 |
| 失败探索 | 失败事实卡 | 保留失败原因和禁止重复的路径 |
| 当前目标、硬约束、关键事实 | 结构化保留 | 不能依赖普通摘要替代 |

压缩前先判断内容的恢复成本。能够从稳定来源重新获取的内容，优先使用引用或重新获取；无法重新确认的关键事实，保留结构化字段。

## 三、分级压缩策略 {/* #二分级压缩策略 */}

压缩按照成本和信息损失逐级升级。每一级完成后重新计算输入预算，预算满足时立即停止：

| 级别 | 处理方式 | 信息损失 | 运行成本 | 典型内容 |
|---|---|---:|---:|---|
| L0 | 选择性装配 | 取决于选择是否完整 | 低 | 只加载当前任务和阶段需要的内容 |
| L1 | 清理与去重 | 极低 | 低 | 重复规则、已消费消息、过期版本 |
| L2 | 结构化投影与外部化 | 低 | 低到中 | 工具输出、日志、长文件、搜索结果 |
| L3 | 重新获取 | 取决于来源 | 中 | 保留索引和查询条件，按需读取原文 |
| L4 | 阶段摘要与轨迹压缩 | 中 | 中到高 | 已完成阶段、失败探索、长对话 |
| L5 | 紧急降级 | 高 | 低到中 | 大幅减少背景、限制能力、请求用户补充 |

推荐的升级顺序：

```text
L0 选择
→ L1 清理
→ L2 投影 / 外部化
→ L3 重新获取
→ L4 结构化摘要
→ L5 紧急降级
```

摘要模型、激进截断和大范围能力裁剪放在后级。前一级无法满足预算时，才进入后一级。

## 四、常见压缩方法 {/* #三常见压缩方法 */}

压缩方法的差异在于“删除多少信息、保留什么结构、细节如何回来”：

| 方法 | 处理方式 | 信息损失 | 适用内容 |
|---|---|---:|---|
| 滑动窗口 | 保留最近若干轮或当前阶段 | 高 | 闲聊、已完成的短交互 |
| 选择性裁剪 | 删除低价值、重复或已消费内容 | 中 | 历史消息、旧尝试 |
| 去重合并 | 合并重复规则、事实和工具结果 | 低 | 重复系统说明、重复查询 |
| 结构化投影 | 原文转换成字段、列表或统计 | 中 | 工具输出、日志、表格 |
| 轨迹裁剪 | 保留当前分支，移除失败分支细节 | 中 | 计划探索、多路径尝试 |
| 摘要 | 提炼阶段结论、事实和待办 | 中到高 | 长对话、阶段完成记录 |
| 外部化引用 | 输入保留预览和可重新读取的位置 | 低 | 大文件、长搜索结果 |
| 重新获取 | 保留索引和查询条件，按需取回原文 | 取决于来源 | 可检索的稳定资料 |

### 1. 滑动窗口 {/* #滑动窗口 */}

按轮次、阶段或消息数量保留最近内容。窗口边界需要与消息关系对齐，工具请求和结果、引用和正文等成组内容不能被拆开。

滑动窗口成本低、延迟小，适合短任务和低价值历史。任务目标、硬约束和关键事实需要单独保留。

### 2. 选择性裁剪与去重 {/* #选择性裁剪与去重 */}

删除已经消费、不会改变下一步决策或被新版本替代的内容；合并重复规则、相同查询结果和重复状态。

裁剪前为内容标记决策价值：

```text
影响下一步决策 → 保留
可以从稳定来源重建 → 引用或重新获取
没有新增信息 → 去重
只影响阅读顺序 → 删除
```

### 3. 结构化投影 {/* #结构化投影 */}

把长文本转换成固定字段，保留模型真正需要的内容：

```text
原始工具输出
→ 关键结果
→ 错误类型
→ 影响范围
→ 可执行下一步
→ 原文引用
```

结构化投影适合日志、表格、搜索结果和接口响应。字段设计要保留异常、边界和来源，避免只留下一个无依据的结论。

### 4. 轨迹裁剪 {/* #轨迹裁剪 */}

复杂任务可能产生多个计划分支和失败尝试。压缩时保留当前有效分支、已确认结论和失败原因，移除已经放弃的探索细节。

失败分支至少留下：

```text
尝试目标
失败原因
已验证的事实
不应重复的路径
```

### 5. 摘要 {/* #摘要 */}

把已经结束的阶段压缩成会影响后续决策的事实：

```text
stage_goal
confirmed_facts
completed_items
failed_assumptions
pending_items
source_refs
```

摘要保留事实和状态变化，删除叙述过程。摘要完成后检查字段、来源和当前版本；摘要失败时保留原内容或暂停发送。

### 6. 外部化引用 {/* #外部化引用 */}

把全文换成短预览和可恢复引用：

```json
{
  "type": "content_preview",
  "summary": "发现 3 个候选文件",
  "omitted": 860,
  "source_ref": "search-result-123",
  "reopen_with": "read_file"
}
```

替换结果需要告诉模型发生了什么、完整内容在哪里、什么时候应该重新读取。

### 7. 重新获取 {/* #重新获取 */}

输入只保留索引、查询条件和版本信息，下一轮按需从文件、知识库或外部系统获取原文。

重新获取适合内容规模大、来源稳定且当前只需要局部细节的场景。取回时校验来源版本和权限，避免同一引用在不同时间返回无法解释的结果。

## 五、压缩决策流程 {/* #四压缩决策流程 */}

一次压缩可以按以下顺序执行：

```text
预测输入增长
→ 找出低价值内容
→ 估算恢复成本
→ 从 L0 开始逐级升级
→ 保留关键事实和来源
→ 生成压缩结果
→ 重新计算预算
→ 校验模型是否仍能继续任务
```

压缩发生在两次模型调用之间。稳定规则和稳定的工具定义应保持在输入前缀，优先处理后部的历史消息、工具结果和阶段材料。压缩会使被替换位置之后的缓存失效，因此不应每轮都压缩；更适合在预算阈值、阶段切换或上下文腐化信号出现时批量处理。

压缩策略由内容特征决定：

| 内容特征 | 优先策略 |
|---|---|
| 重复且可丢弃 | 裁剪 |
| 原文很长且可重新读取 | 替换 |
| 阶段已经结束且结论稳定 | 摘要 |
| 来源稳定、当前只需局部内容 | 重新获取 |
| 目标、约束和关键事实 | 原样或结构化保留 |

## 六、什么时候触发 {/* #五什么时候触发 */}

### 1. 预测触发 {/* #预测触发 */}

发送请求前，根据输入长度、输出预留和预计新增内容判断下一轮是否会超预算：

```text
总窗口
− 当前输入
− 输出预留
− 工具结果增长预估
< 安全阈值
```

达到阈值后先压缩，再发起模型调用。

### 2. 响应触发 {/* #响应触发 */}

服务端返回上下文超限、输出截断或输入拒绝时，进入降级压缩。响应触发只能作为兜底，不能承担全部压缩工作。

### 3. 阶段触发 {/* #阶段触发 */}

阶段结束、用户接管、长时间等待或任务即将切换工作模式时，提前整理已经完成的内容，减少下一阶段的输入噪声。

### 4. 腐化触发 {/* #腐化触发 */}

即使输入没有超预算，也可以根据运行信号提前压缩：

- 模型重复询问已经确认的事实；
- 相同工具和参数连续出现；
- 旧版本和新版本事实同时进入输入；
- 关键证据被大量低价值结果淹没；
- 当前阶段已经变化，但旧阶段材料仍然占据主要空间。

腐化触发应优先执行选择性裁剪、去重和结构化投影，再决定是否需要摘要。

## 七、压缩后必须保留什么 {/* #六压缩后必须保留什么 */}

压缩结果至少保留：

- 当前任务目标和硬约束；
- 当前阶段和未完成事项；
- 已确认事实及其来源版本；
- 已经发生并会影响后续判断的结果；
- 已证伪的假设和不应重复的路径；
- 重新读取细节所需的引用和查询条件；
- 当前预算和剩余能力范围。

这些内容可以换成结构化字段或短摘要，但语义必须保持稳定。普通叙述可以被压缩，决策依据不能被压缩成无法验证的模糊句子。

### 1. 将摘要作为待验证的派生视图 {/* #将摘要作为待验证的派生视图 */}

原始任务事实与执行记录保留在状态或可靠存储中，摘要只负责表示当前需要看到的内容。模型生成摘要不能覆盖原始授权、改变动作状态，或把“正在等待结果”改成“已经完成”。

发布新摘要前，检查目标范围、未完成项、未知副作用、审批有效期和来源引用是否保留。字段存在还不够，关键值应与权威状态比对。摘要未通过时保留旧视图和原始材料，改用局部裁剪、引用或缩小任务；原始输入仍超限时暂停调用，不能强行发送。

压缩任务也可能失败。长结果在进入历史时就分页或外部化，可以减少临近上限才请求摘要的压力。预留给压缩的输入、输出和费用必须计入[任务预算](../04-decision/agent-brain.md)。

## 八、配置摘要中间件时，先确认它修改哪一层 {/* #框架中的压缩定制 */}

### 1. 配置触发线、保留区和摘要要求 {/* #1-配置触发线保留区和摘要要求 */}

LangChain 的 `SummarizationMiddleware` 是在模型调用前压缩旧消息的中间件，可通过 `create_agent()` 的 `middleware` 参数接入。其关键配置决定何时压缩、保留多少近期消息，以及如何提取可继续执行的信息。

| 配置 | 用途 | 业务定制方式 |
| --- | --- | --- |
| `model` | 生成摘要的模型 | 单独评测事实保留能力；切换摘要模型后重新核对预算 |
| `trigger` | 触发压缩的阈值 | 可按 token、消息数或窗口比例设定，给工具目录与输出预留空间 |
| `keep` | 保留的近期消息范围 | 围绕当前阶段选择，保留未闭合的工具调用及其结果 |
| `summary_prompt` | 摘要提取要求 | 要求保留目标、已确认事实、约束、证据位置、未完成动作和未知结果 |
| `token_counter` | 消息长度统计方法 | 与实际模型和输入形态校准，不能把消息估算等同于整次请求用量 |

按窗口比例触发时，本版本读取的是摘要模型的窗口信息。摘要模型与执行模型不同时，应核对两者容量，不能直接认为 `fraction` 对应执行模型的窗口。

### 2. 识别消息替换带来的恢复影响 {/* #2-识别消息替换带来的恢复影响 */}

LangChain 1.3.7 的 `libs/langchain_v1/langchain/agents/middleware/summarization.py` → `SummarizationMiddleware.before_model()` 在第 388–394 行返回以下更新；摘要生成和切分代码省略。`RemoveMessage` 是消息删除指令，`REMOVE_ALL_MESSAGES` 表示清空原消息集合。

```python
return {
    "messages": [
        RemoveMessage(id=REMOVE_ALL_MESSAGES),
        *new_messages,
        *preserved_messages,
    ]
}
```

这是对 State 的消息替换，后续恢复也会使用替换后的消息。需要保留的动作账本、审批绑定和文档版本应独立存放；若要按需查原文，还要另设归档与检索入口。只在 `wrap_model_call` 中裁剪请求视图，则不会自动产生同样的状态替换。

### 3. 接入 Deep Agents 前检查已有压缩策略 {/* #3-接入-deep-agents-前检查已有压缩策略 */}

Deep Agents 已装配摘要与大结果外部化能力。本文核对的 0.6.12 源码快照中，`graph.py` → `_apply_custom_middleware()` 按中间件的 `.name` 合并：同名实现原位替换，不同名称则插入。换成普通摘要中间件可能丢掉原有归档或溢出处理；换一个名字又可能让两套压缩同时运行。应检查最终装配结果及实际 hook，不能仅凭配置列表判断。

文档维护任务可用“摘要后继续编辑”验收：检查目标页面版本、禁止修改的范围、已发布动作 ID 和待核实引用是否仍可获得；再模拟一次上下文超限，验证降级路径。实现与快照范围见[上下文摘要与外部化](../../../application-notes/engineering/langchain-series/deepagents/10-summarization-and-context-offloading.md)和[上下文处理](../../../application-notes/engineering/langchain-series/langchain/09-context-and-privacy.md)。

## 九、常见压缩失败 {/* #七常见压缩失败 */}

| 失败现象 | 原因 | 调整方式 |
|---|---|---|
| 每次都调用摘要模型 | 没有区分可删除和可重建内容 | 先裁剪、替换，再考虑摘要 |
| 摘要保留了过程，丢失了结论 | 以对话长度为目标 | 按后续决策字段组织摘要 |
| 压缩后模型重复失败探索 | 没有保留失败假设 | 建立失败事实卡 |
| 引用存在但无法重新读取 | 缺少来源、版本或查询条件 | 引用与恢复信息一起保存 |
| 工具请求和结果被拆开 | 按字符或最近消息粗暴截断 | 按消息关系和阶段边界处理 |
| 旧事实与新事实同时保留 | 没有版本和失效标记 | 新版本替换旧版本，保留变更原因 |
| 压缩结果超预算 | 没有给摘要和引用预留空间 | 压缩前预留输出与结构开销 |

## 十、验收方式 {/* #八验收方式 */}

### 1. 任务连续性 {/* #任务连续性 */}

压缩前后的模型能够识别同一个目标、约束和当前阶段。

### 2. 事实准确性 {/* #事实准确性 */}

关键事实、来源版本和已确认结论保持一致，旧版本不会静默覆盖新版本。

### 3. 细节可恢复 {/* #细节可恢复 */}

模型需要原文细节时，可以根据引用、位置和查询条件重新读取。

### 4. 预算稳定 {/* #预算稳定 */}

压缩后输入落在预期预算内，并为模型输出和后续工具结果保留增长空间。

评估压缩收益时，将摘要生成、缓存失效和原文重新读取的成本一起计入。频繁压缩虽然使单轮输入变短，却可能增加总延迟与费用。

### 5. 失败可回退 {/* #失败可回退 */}

摘要模型失败、来源不可用或版本冲突时，系统保留原内容、重新获取或暂停发送。

可以设计一组对照任务，刻意把关键约束放在早期消息，把否定条件放在长工具结果中，并在中途修改目标。压缩后继续运行，检查旧目标是否失效、未知动作是否仍待确认、引用是否能重新读取。不要只比较摘要文本相似度；最终应检查这些事实是否仍正确影响执行。

建议跟踪：

```text
压缩前后 Token 数
关键事实保留率
重新读取成功率
压缩后重复失败率
摘要失败率
任务完成率
```

## 十一、简单任务的处理方式 {/* #九简单任务的处理方式 */}

短任务、低信息量任务和可整体重算的只读任务，可以优先使用裁剪和结构化引用。长任务、阶段切换频繁或证据恢复成本高的任务，再引入摘要、重新获取和版本管理。
