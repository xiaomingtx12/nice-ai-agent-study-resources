# 证据进入上下文：渐进发现与多模态核验

Agent 需要为当前判断取得足够的证据。把目录读完、把 PDF 转成文本、把检索结果全部塞进输入，都不能单独证明这个目标已经达到。证据获取要回答三个问题：还缺什么，去哪里找，取得以后怎样保留它的含义。

以分析服务延迟为例，日志能指出异常时间，查询结果能说明请求分布，架构图能解释依赖关系。三者需要对齐到同一服务、版本和时间窗，才有可能支持一个共同判断。

## 一、先列证据要求，再分配输入预算

把“分析延迟升高”拆成可检查的问题：异常是否真实存在、影响哪些请求、发生在什么版本、候选原因有什么支持与反例。为每个问题登记必要材料，而不是先决定加载多少条搜索结果。

| 材料类别 | 处理方式 | 延迟调查中的例子 |
| --- | --- | --- |
| 当前判断不可缺少 | 保留精确内容、版本和位置 | 错误码、时间窗、统计分母、部署版本 |
| 有帮助但较长 | 保留摘要，附原始材料引用 | 多页部署记录、重复日志区段 |
| 可能在下一步需要 | 保存可发现的索引 | 相邻服务文档、尚未命中的配置 |
| 无权访问或已经失效 | 不进入当前证据集 | 其他租户数据、被新版本替代的说明 |

权限和有效性先于相关性排序。不能让“语义上很像”把无权使用的材料带入上下文。关键限制也不能在预算不足时静默裁掉：可以缩小当前问题、外部化背景材料，或停止并报告缺证。

材料还要经过“找到—读取—装配—使用”几个边界。保存文件引用只证明资料可取回；真正判断时，应能查明模型看到了哪一段、哪些部分被摘要或截断。相关机制见[上下文装配](./agent-context-management.md#材料可访问不代表模型已经看见)。

## 二、用渐进发现收敛搜索范围

### 1、从广泛定位进入局部核验

搜索可以分成四步，每一步都用上一轮新增的证据调整范围。

1. **定位候选。** 用目录、文件名、标题、错误码和短片段寻找入口，避免立即加载大批全文。
2. **读取关键上下文。** 打开命中的函数、日志前后文或文档小节，确认命中内容是否讨论当前对象。
3. **沿依赖补证。** 从调用方追到实现、配置和测试，从图表追到数据口径，从结论追到来源。
4. **核对适用范围。** 确认版本、时间、权限和前置条件，检查有没有足以改变结论的反例。

例如搜索到一次“连接超时”，只能定位症状。继续读取请求前后日志、连接池配置和同一时间的请求量，才可能区分服务不可达、资源耗尽与单次抖动。不能直接把搜索命中词写成根因。

### 2、把探索进度留给下一轮

探索记录至少保留当前问题、已读位置、排除项及理由、未决假设、待查入口和剩余预算。下一轮应基于这些记录选动作，避免不断更换近义词却反复打开同一资料。

重复读取有时是必要的：材料变更、摘要缺细节、发现新解释，都可以成为重读理由。记录版本或新问题，才能区分有价值的回查与无进展重复。

停止条件也要提前定义。关键结论已经有适用证据时结束；连续搜索没有新增证据时换来源或缩小问题；预算耗尽时交付已确认结果和缺口。搜索结果很多并不构成继续搜索的理由。

## 三、按信息结构选择表示方式

多模态证据包含图像、扫描页等材料；日志、数据库查询则是不同结构的数据来源。它们可以进入同一证据链，但各自需要保留的结构不同。

| 来源 | 当前输入应保留什么 | 容易丢失什么 | 核验方式 |
| --- | --- | --- | --- |
| 日志 | 时间、请求身份、错误类型、必要前后文 | 跨行关联、重试顺序、时区 | 按请求与时间窗回查 |
| 查询结果 | 查询条件、快照、字段、单位和分母 | 过滤条件、空值、重复行 | 重跑受控查询或复核快照 |
| 表格 | 表头、行列关系、合并单元格语义、脚注 | 单位继承、跨页表头、汇总口径 | 对照原表，精确计算交给程序 |
| 扫描页 | 提取文本、页码、区域、识别警告 | 小数点、负号、编号和批注 | 对关键字段查看页面图像 |
| 图与截图 | 图例、坐标轴、布局、箭头和截取范围 | 被裁掉的标尺、遮挡、空间关系 | 查看原图与必要局部 |

转换结果是一种派生表示。文字抽取成功，不代表图中的依赖方向也被保留；表格行被转成句子后，原来属于上一列表头的单位可能失去归属。对会影响结论的结构，应保留原件位置并允许回读。

精确数值计算优先使用可核验的结构化数据。若只有截图，先核对字段和单位，再计算；无法辨认的数字保持未知，不能通过上下文补一个看似合理的值。

## 四、融合前先对齐对象与口径

一份证据卡可以包含：问题与命题、对象身份、内容或工件引用、来源版本、时间范围、位置、提取方式、单位口径、访问范围，以及仍未消除的缺口。这是数据契约建议，具体字段按任务选择。

假设监控图显示请求耗时上升，日志却没有明显异常，不能直接认定其中一个来源有错。先核对监控统计的是全部请求还是某个接口，曲线是平均值还是尾部值，日志是否采样，两者时间窗是否一致。口径不同产生的差异，应保留为限定条件。

对齐后仍然冲突的证据，进入待裁决集合：保留双方值、来源、时间和冲突点，选择补充查询、明确适用版本或转交判断。不要在生成摘要时将差异抹成“总体正常”。

## 五、用转换损失和缺证场景验收

取一组包含原件和已确认结论的材料，检查证据链是否保留了真正影响判断的信息。

- 表格跨页后，单位和列名能否正确关联到数据；金额、比例和数量会不会被混用。
- 图片被裁剪或 OCR 识别不清时，能否暴露缺口并回读原件。
- 两份资料版本不同，能否保留差异并选择适用版本。
- 关键限制位于长文末尾时，能否进入实际决策输入。
- 同一查询连续没有新增证据时，能否停止并交付未决项。

观察获取成本时，把搜索次数、全文读取量、转换失败和重复读取分别记录；观察质量时，检查结论能否回到原始位置，以及必需证据是否完整。追求较少输入的前提，是当前判断所需的信息没有被丢掉。
