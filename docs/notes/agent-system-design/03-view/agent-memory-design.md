# 记忆设计：让模型记住真正有用的内容

> **模块本质：** 管理跨任务信息的写入、读取、更新与遗忘，让事实、偏好和经验在适用范围内持续复用，并阻止过期、冲突或未经确认的内容成为决策依据。

记住更多内容会增加冲突和维护成本，旧信息何时退出同样需要设计。

模型每轮调用都面对有限输入。用户偏好、项目约定、过去的处理结果和稳定经验如果只停留在当前对话中，后续任务就会重复询问、重复试错和重复装配。

记忆系统需要同时控制四件事：

```text
什么内容值得记住
→ 什么时候写入
→ 什么时候读取
→ 什么时候更新或遗忘
```

## 一、记忆解决什么问题 {/* #一记忆解决什么问题 */}

### 1. 跨任务复用事实 {/* #跨任务复用事实 */}

用户偏好、项目约定、稳定实体属性和长期配置可以在后续任务中直接使用，减少重复确认。

### 2. 复用历史经验 {/* #复用历史经验 */}

过去成功的方法、失败原因和修复步骤可以帮助模型缩短探索路径。

### 3. 保留交互连续性 {/* #保留交互连续性 */}

最近确认、未完成约定和用户明确要求可以在多轮交互中保持一致。

### 4. 控制模型输入规模 {/* #控制模型输入规模 */}

长期信息保存在记忆系统中，当前调用只读取与目标相关的内容，避免把全部历史永久放进输入。

## 二、记忆按用途分型 {/* #二记忆按用途分型 */}

不同记忆的写入门、可信度和保留时间不同：

| 类型 | 典型内容 | 主要价值 | 常见保留方式 |
|---|---|---|---|
| 会话记忆 | 当前对话、最近确认、临时偏好 | 保持当前交互连续 | 随会话结束清理或归档 |
| 事实记忆 | 用户偏好、项目约定、稳定属性 | 减少重复确认 | 带来源和有效期保存 |
| 情节记忆 | 过去任务、关键决定、处理结果 | 提供历史背景 | 按主题和时间检索 |
| 经验记忆 | 成功方法、失败模式、修复步骤 | 缩短后续探索 | 经过验证后提升可信度 |

当前任务的目标、阶段和待处理事项属于任务运行状态；跨任务仍然有读取价值的内容才进入长期记忆。

## 三、常见记忆方案 {/* #三常见记忆方案 */}

记忆方案由保存对象、访问方式和保留周期共同决定：

| 方案 | 保存方式 | 适用场景 | 主要代价 |
|---|---|---|---|
| 最近消息缓存 | 保留最近若干轮对话 | 短会话连续交互 | 超过窗口后快速失效 |
| 滚动摘要 | 持续更新阶段或会话摘要 | 长对话、长任务 | 摘要会产生信息损失 |
| 结构化档案 | 用键值或字段保存偏好、配置和事实 | 用户偏好、项目约定 | 需要严格更新和冲突规则 |
| 情节记忆库 | 保存任务经历、决定和结果 | 回顾历史任务、相似案例 | 检索和隐私管理成本高 |
| 语义记忆库 | 文本切片加向量和元数据 | 模糊查询、经验召回 | 相似度负责召回，事实确认需要额外校验 |
| 图记忆 | 保存实体、关系和时间变化 | 多实体、多跳关系 | 构建和维护复杂 |
| 程序性记忆 | 保存经过验证的做法和步骤 | 重复任务、经验复用 | 需要验证、版本和废弃机制 |
| 分层组合 | 短期缓存、结构化事实、检索记忆组合 | 生产级 Agent | 读取路由和一致性复杂 |

简单任务可以从最近消息缓存或结构化档案开始；长任务和复杂领域再增加摘要、情节、语义或图结构。

## 四、写入机制 {/* #四写入机制 */}

模型输出、用户反馈和外部结果都只能产生记忆候选，写入长期记忆需要经过筛选：

```text
候选生成
→ 判断类型
→ 检查来源和可信度
→ 判断读取价值
→ 去重与冲突检查
→ 隐私和保留期检查
→ 选择存储方案
→ 写入并建立索引
```

### 1. 常见写入方式 {/* #常见写入方式 */}

| 写入方式 | 触发信号 | 适合内容 | 控制方式 |
|---|---|---|---|
| 用户显式保存 | 用户说“记住、以后都这样” | 偏好、约定、长期配置 | 记录原句和确认时间 |
| 规则提取 | 命中格式、字段或业务事件 | 邮箱、项目名、配置项 | 规则校验和字段白名单 |
| 结构化模型提取 | 对话或结果中出现候选事实 | 偏好、事实、经验候选 | JSON Schema、置信度和人工确认 |
| 记忆工具调用 | 模型主动调用 `remember` | 明确的事实或经验 | 工具权限、参数校验和去重 |
| 任务结束归纳 | 任务完成或阶段结束 | 情节记忆、成功方法、失败原因 | 只提取影响后续任务的内容 |
| 用户反馈回写 | 用户纠正、确认或否定 | 事实更新、偏好修正 | 以用户决定更新版本 |
| 离线批处理 | 定时整理历史记录 | 聚类、摘要、经验提升 | 评测后发布，支持回滚 |

推荐组合：

```text
显式保存 / 用户纠正
→ 确认表达者的权限与适用范围
→ 保存偏好或待验证事实

模型提取 / 任务归纳
→ 生成候选
→ 校验或等待确认
→ 写入长期记忆
```

### 2. 候选记忆格式 {/* #候选记忆格式 */}

写入前先统一成结构化候选。下面是用于说明字段含义的偏好记录示例：

```json
{
  "kind": "preference",
  "subject": "user:42",
  "content": "偏好使用中文回答",
  "source": "user_message:183",
  "confirmation": "user_confirmed",
  "valid_until": null
}
```

### 3. 写入判断 {/* #写入判断 */}

至少回答：

- 内容属于事实、偏好、经历还是经验；
- 来源是否可靠，是否需要用户确认；
- 后续任务读取它会改变什么决策；
- 内容是否包含敏感信息；
- 是否已经存在相同或相反记忆；
- 需要保留多久。

一次性上下文、未验证猜测和没有后续读取价值的内容，不进入长期记忆。

### 4. 确认等级 {/* #确认等级 */}

记忆需要记录确认状态：

```text
user_confirmed
system_verified
model_inferred
unverified_candidate
```

确认等级影响读取优先级和是否允许直接注入模型输入。推断内容可以作为候选线索，确认事实可以作为稳定依据。

用户可以确认自己的表达偏好，但不一定能确认另一个租户的配置或覆盖组织策略。确认等级需要结合字段的权威来源判断，不能把所有“用户说过”统一升级为全局事实。模型自报置信度也不等于经过校准的正确概率。

### 5. 写入后的处理 {/* #写入后的处理 */}

写入成功后完成三项操作：

1. 保存主记录、来源、版本和保留策略；
2. 更新关键词、向量或图索引；
3. 让旧版本失效、降权或进入冲突集合。

主记录和索引需要使用同一版本号，避免检索到已经失效的内容。

## 五、读取流程 {/* #五读取流程 */}

读取需要从候选集合中选出当前任务真正有用的内容：

```text
范围过滤
→ 候选召回
→ 可信度排序
→ 新鲜度检查
→ 冲突处理
→ 形成记忆片段
```

### 1. 范围过滤 {/* #范围过滤 */}

先按用户、租户、项目、主题和时间过滤，确保记忆属于当前任务。

### 2. 候选召回 {/* #候选召回 */}

可以使用关键词、向量、时间、实体和规则组合召回。召回只负责找到候选，不负责确认事实。

### 3. 可信度排序 {/* #可信度排序 */}

排序至少考虑：

```text
来源可靠性
+ 确认等级
+ 新鲜度
+ 当前任务相关性
− 冲突风险
```

### 4. 形成记忆片段 {/* #形成记忆片段 */}

进入模型输入的记忆片段带有必要的状态说明：

```text
内容
来源
确认状态
有效时间
与当前任务的相关原因
```

过期、冲突或仅供参考的记忆需要显式标记，避免被模型当作无条件事实。

## 六、更新、冲突与遗忘 {/* #六更新冲突与遗忘 */}

### 1. 更新 {/* #更新 */}

新信息改变旧事实时，保留版本关系、更新时间和变更来源。当前有效版本进入后续读取，旧版本保留到保留期结束或完成删除请求。

### 2. 冲突 {/* #冲突 */}

冲突判断先对齐实体、字段和适用范围。“测试环境使用旧接口”和“生产环境使用新接口”可以同时成立；不同作用域的内容不能仅凭语义相似就互相覆盖。

| 新旧内容的关系 | 处理方式 |
| --- | --- |
| 同一事实的重复表达 | 合并来源，避免重复占据召回位置 |
| 同一范围内发生有效更新 | 新记录指向被替代版本，旧记录退出当前召回 |
| 条件不同，各自成立 | 保留条件分支，读取时匹配当前环境 |
| 来源矛盾且无法判定 | 保留冲突记录，不向模型注入一个无条件结论 |
| 当前任务的临时要求 | 优先用于本次任务，不自动覆盖长期偏好 |

只有在相同范围、相同权威来源或已经核实的版本链内，较新记录才适合替代旧记录。网页更新时间更晚、用户刚刚提到某种猜测，都不足以覆盖可信配置。

写入时可按实体、字段和范围查找潜在冲突，再辅助使用语义检索。模型负责提出候选关系，确定性写入层负责版本检查；两个并发更新基于同一旧版时，应重新合并或报告冲突。主记录、索引和读取缓存也要一起更新有效版本。

### 3. 降权 {/* #降权 */}

长期未使用、来源不稳定或被多次否定的记忆降低读取优先级。降权保留数据，适合处理暂时不活跃但仍可能有价值的内容。

使用频率只能反映热度。错误记忆被反复召回，也可能越来越“活跃”；应区分被召回、被采用和经结果验证有效。提升经验优先级时，优先使用独立验收或明确反馈，避免记忆因为自己的重复出现而不断获得强化。

长期约束、访问规则和用户明确要求保留的信息不应只按时间衰减。可过期的知识由有效期控制，低频但必须适用的规则走确定性读取；相关边界见 [RAG 中的约束与证据](./rag-engineering.md)。

### 4. 删除 {/* #删除 */}

用户撤回、租户隔离、保留期到期和隐私请求都可以触发删除。删除需要覆盖主记录、索引、缓存和备份中的可识别副本。

不可即时改写的备份需要声明保留与到期清理策略，并在恢复备份后重新应用删除记录。验收应检查在线读取与历史恢复两条路径，避免已删除内容从旧备份重新进入索引。

## 七、最小数据模型 {/* #七最小数据模型 */}

```text
Memory {
  id
  kind
  content
  scope
  source_refs
  confidence
  confirmation
  valid_from
  valid_until
  version
  last_used_at
  retention_policy
}
```

字段设计围绕四个判断展开：

```text
它是什么
从哪里来
现在是否有效
以后如何处理
```

内容、来源、确认状态和有效期分开保存，方便更新、冲突处理和删除。

## 八、把记忆策略接到 Store 和文件后端 {/* #框架中的记忆接入 */}

### 1. 按读取方式选择存储入口 {/* #1-按读取方式选择存储入口 */}

LangGraph 的 Store 提供按命名空间与键读写数据的接口，适合承载跨任务信息；是否持久化、是否支持语义检索，要看具体实现和索引配置。checkpointer 保存同一执行线的现场，不能仅因它记住了上一轮消息，就把它当成完整的长期记忆系统。

Deep Agents 的 Backend 是文件工具背后的存储接口，可以把不同路径分配给不同存储。

| 接入方式 | 适合的数据 | 仍需业务处理的事情 |
| --- | --- | --- |
| `StateBackend` | 当前执行线中的草稿和工作文件 | 文件随状态保存；持久性取决于检查点配置 |
| `StoreBackend` | 跨任务可复用的文件 | 显式定义用户、租户、项目范围，配置持久 Store |
| `CompositeBackend` | 工作文件与长期文件并存 | 按路径路由，并分别设置写入与清理规则 |
| `create_deep_agent(memory=[...])` | 项目约定等固定入口文件 | 装配文件内容进入提示词，管理版本与刷新时机 |

`MemoryMiddleware` 是读取指定记忆文件并装配提示词的中间件。配置 `memory` 不会自动生成事实抽取、冲突裁决、语义召回或遗忘策略。项目约定适合用文件入口；数量持续增长的事实记录更适合经过查询服务筛选后注入。

### 2. 路径路由与租户隔离分别配置 {/* #2-路径路由与租户隔离分别配置 */}

下面来自 Deep Agents 0.6.12 源码快照的 `libs/deepagents/tests/unit_tests/backends/test_composite_backend.py` → `test_composite_backend_filesystem_plus_store()`，节选后端装配部分。省略临时目录初始化和后续断言；`root` 是测试目录。

```python
fs = FilesystemBackend(root_dir=str(root), virtual_mode=True)
mem_store = InMemoryStore()
store = StoreBackend(store=mem_store, namespace=lambda _rt: ("filesystem",))
comp = CompositeBackend(default=fs, routes={"/memories/": store})
```

这个测试把普通文件留在文件系统，把 `/memories/` 路由到 Store；`InMemoryStore` 只在进程内保存数据。固定的 `("filesystem",)` 适合测试，业务中应由已验证身份计算命名空间，例如按租户、用户和项目划分。路径前缀只决定数据去哪儿，不自动检查调用者是否有权读取。

### 3. 在写入服务中管理候选与已确认记忆 {/* #3-在写入服务中管理候选与已确认记忆 */}

文档维护 Agent 可以将“这个项目偏好短标题”提交为候选偏好，经过用户确认或既定规则验证后再写入正式记录。读取服务根据任务范围、版本和有效期筛选，返回内容与来源；不要给任意模型工具直接覆盖所有长期记忆的权限。

验收时让同一用户切换两个项目，确认偏好按范围生效；再撤回一条已进入摘要的记录，检查 Store、检索索引、缓存和后续上下文都不再使用它。后端读写成功只验证存储能力，这些用例才验证业务记忆策略。源码与快照边界见[Backend 实现](../../../application-notes/engineering/langchain-series/deepagents/04-backend-protocol-and-implementations.md)和[MemoryMiddleware](../../../application-notes/engineering/langchain-series/deepagents/13-memory-middleware.md)。

## 九、常见记忆失败 {/* #八常见记忆失败 */}

| 失败现象 | 原因 | 调整方式 |
|---|---|---|
| 所有对话都进入长期记忆 | 缺少写入门 | 先判断类型、读取价值和保留期限 |
| 模型猜测被当成事实 | 缺少确认等级 | 标记推断状态，等待验证 |
| 旧偏好覆盖当前明确要求 | 缺少新鲜度和优先级 | 当前任务要求优先，旧记忆降权 |
| 不同项目的记忆混用 | 范围过滤不足 | 按用户、租户和项目隔离 |
| 向量相似度直接决定覆盖 | 把召回当成事实判断 | 召回、排序、确认分开处理 |
| 用户要求忘记后仍能召回 | 只删除主记录 | 同步清理索引、缓存和副本 |
| 经验记忆越来越多但没有帮助 | 缺少使用反馈 | 根据任务结果调整可信度和保留期 |

## 十、记忆系统的验收 {/* #九记忆系统的验收 */}

### 1. 读取价值 {/* #读取价值 */}

新任务能够读取已确认的偏好、项目约定和有效经验，并减少重复询问或试错。

### 2. 事实准确 {/* #事实准确 */}

过期、冲突和推断记忆带有明确标记，当前任务的明确要求优先生效。

### 3. 范围隔离 {/* #范围隔离 */}

不同用户、租户和项目之间的记忆完全隔离。

### 4. 删除有效 {/* #删除有效 */}

用户撤回或删除后，相关内容不再被召回，也不再从缓存和索引中出现。

### 5. 经验回流 {/* #经验回流 */}

成功和失败结果能够更新经验可信度，错误经验不会持续影响后续任务。

建议跟踪：

```text
记忆命中率
重复询问减少率
过期记忆命中率
冲突记忆比例
用户删除后的残留率
记忆对任务成功率的影响
```

记忆系统的质量，取决于模型能否在正确的时间读取正确的内容，并且知道这条内容的来源、可信度和有效范围。
