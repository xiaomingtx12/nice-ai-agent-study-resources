# Agent 评测篇

> **占位骨架** —— 这一篇是 Agent 评测的工程化骨架，关键判断速览已列条目，三段以下的正文待真实评测样本出现后回填。打破"无样本不立条"规则一次的理由：评测作为方法学，其工程化要点（评测什么 / 怎么搭 / 怎么回流）和 RAG 评测是同构的，先把骨架立住不至于未来补时还要回头重排坐标。

读这篇之前你应该已经读过 [RAG 评测篇](./rag-evaluation.md)（知道评测这一刀的通用范式：评估集 / 指标 / 排查顺序 / 反模式）。本篇聚焦 Agent 评测和 RAG 评测的**结构性差异**：

- 评测对象从"单次检索 + 单次生成"变成**多轮决策链**（可能跨工具、跨 Agent、跨 Session）
- 失败模式从"喂错料"扩展到**幻觉 / 死循环 / 工具误用 / 权限越权 / 多 Agent 协调失败** 五类
- 评测粒度从 chunk 级下沉到**工具调用级、决策节点级、整图完成级** 三层

## 一、动机

Agent 的失败模式比 RAG 复杂——RAG 答错了可以归到"检索"或"生成"两层之一；Agent 答错了可能是：

- 选错了工具（意图识别错）
- 调了正确的工具但参数错（Schema 校验没拦住）
- 调对了工具但顺序错（大脑的 Plan 不合理）
- 单 Agent 跑不出来（多 Agent 拆得不对）
- 跑出来了但用户不满意（最后一公里的体验问题）

没有评测就盲调——而且 Agent 调试的"调试单位"不是行号，是**一段决策链**。

## 二、关键判断速览

- **三层评测粒度**：整图完成级（任务成没成）/ 决策节点级（哪一步选错了）/ 工具调用级（参数 / Schema / 权限对不对）
- **五类失败模式**：幻觉 / 死循环 / 工具误用 / 权限越权 / 多 Agent 协调失败 —— 每类都得有专项 case
- **Trace 是 Agent 评测的 ground truth**：每一步都要有可回放的 trace，评测不靠日志靠 trace 重放
- **离线评估集覆盖三类场景**：happy path / 边界 case / 已知失败模式回归
- **在线 A/B 走影子模式起步**：直接上线跑流量风险大，先影子模式对照"如果走另一条路会怎样"

## 六、反模式

> 待真实样本回填。先列几条已知的：

- 用 RAG 评测的指标直接套 Agent 评测（chunk 级 Recall ≠ 决策链正确率）
- 评测只看"任务完成 / 没完成"二元（漏掉"完成得对不对"和"完成得是否高效"）
- Trace 只在出错时记录，正常路径没 trace，事后无法回放分析
- 评测集只覆盖 happy path，不覆盖死循环 / 越权 / 多 Agent 协调失败
- 评测离线跑一套指标就上线，不做影子模式对比
