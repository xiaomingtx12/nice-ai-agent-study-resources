# Agent 操作空间：工作区、沙箱与资源边界

> 操作空间的核心本质，是把 Agent 的动作绑定到一个范围明确、资源受限、可以撤销和审计的执行环境中。

权限回答“这个动作能不能做”，操作空间回答“即使能做，也只能在哪里做、能接触什么、最多消耗多少”。模型可以提出读文件、执行命令、访问网络和生成产物，但真实执行必须落在一个明确的空间合同中。

```text
创建空间
→ 绑定任务和策略
→ 执行动作
→ 导出受控产物
→ 撤销访问
→ 清理或保留
```

## 四类空间边界

| 边界 | 约束对象 | 典型规则 |
|---|---|---|
| 工作区 | 文件和目录 | 根目录、挂载、读写范围、导出目录 |
| 进程 | 命令和系统调用 | 可执行程序、环境变量、子进程和进程树 |
| 网络 | 出站连接和服务 | 域名、端口、代理和凭据范围 |
| 资源 | 时间和消耗 | CPU、内存、磁盘、文件大小、并发和超时 |

四类边界需要同时生效。允许写文件但能访问整台机器，或者能访问网络但没有时间和资源上限，都无法形成可控的执行环境。

## 工作区合同

每个任务运行时都应获得一份明确的空间合同：

```text
Workspace {
  run_id
  root
  mounts
  read_scopes
  write_scopes
  exec_policy
  network_policy
  resource_limits
  expires_at
}
```

关键字段的作用：

- `root`：实际执行器解析和校验的根目录；
- `mounts`：区分只读资料、可写目录和产物导出区；
- `read_scopes` / `write_scopes`：限定真实读写范围；
- `exec_policy`：允许的命令、参数和进程行为；
- `network_policy`：出站域名、端口和连接方式；
- `resource_limits`：时间、内存、磁盘、进程和并发上限；
- `expires_at`：空间合同的有效期。

凭据、宿主目录和其他租户目录默认不挂载。路径字符串中出现了某个目录名，不代表执行器就允许访问该目录。

## 文件和路径边界

文件操作必须在真实系统调用前检查最终目标：

1. 规范化路径并解析符号链接；
2. 确认最终路径仍在允许的读写范围内；
3. 检查文件类型、大小、扩展名和操作类型；
4. 将写入限制在任务工作区；
5. 只有登记过的产物才能导出；
6. 记录实际路径、动作、大小和结果。

相对路径、`..`、符号链接、挂载点和并发替换都可能让字符串前缀检查失效。安全判断必须靠执行器最终打开的路径和文件句柄。

## 进程和命令边界

允许 Agent 执行命令时，需要明确：

- 可执行程序和参数是否在白名单内；
- 工作目录和环境变量由谁注入；
- 子进程和后台进程是否受控；
- 文件描述符和标准输入输出如何继承；
- 进程树如何被取消和回收；
- 命令退出后是否仍有后台副作用。

容器或独立进程只是隔离手段，不能替代命令、进程和资源策略。沙箱内部仍可能访问错误的挂载、启动无法回收的后台进程或消耗无限资源。

## 网络边界

网络访问应从默认关闭开始，按任务需要开放：

- 域名和端口白名单；
- 代理和 DNS 行为；
- 请求方法和上传范围；
- 可使用的凭据；
- 请求超时、响应大小和并发；
- 网络日志中的敏感信息处理。

网络允许访问某个域名，不代表可以访问该域名下的全部资源。资源身份、租户范围和凭据权限仍然要在执行前检查。

## 资源边界

资源上限要覆盖单次动作和整个任务：

```text
wall_clock_timeout
cpu_limit
memory_limit
disk_limit
file_size_limit
process_limit
concurrency_limit
```

资源耗尽时，运行时需要记录已消耗的范围和是否产生部分副作用。进程被终止不等于外部动作已经回滚，后续循环应根据真实状态决定查询、补偿或停止。

## 产物如何离开空间

工作区中的文件不能自动成为任务结果。产物导出应经过登记和检查：

```text
生成产物
→ 校验路径和类型
→ 检查大小和敏感内容
→ 生成产物引用
→ 导出到允许位置
```

导出的产物至少要记录任务 ID、路径或对象 ID、版本、生成动作和校验结果。临时文件、缓存和凭据不应随着产物一起导出。

## 空间生命周期

```text
provision
→ bind
→ execute
→ export
→ revoke
→ cleanup / retain
```

- `provision`：创建目录、挂载、网络和资源配额；
- `bind`：绑定任务、租户、权限版本和策略版本；
- `execute`：每次动作进入执行器时重新检查空间合同；
- `export`：只导出登记且通过检查的产物；
- `revoke`：任务取消、策略变化或合同过期时撤销句柄；
- `cleanup / retain`：按保留策略清理临时内容，保留必要的产物和审计引用。

任务恢复时不要直接复用已经过期的沙箱句柄。根据新的权限、策略和资源配额创建新空间，再决定哪些产物可以读取、哪些动作可以继续。

## 空间边界与权限边界

两者需要同时判断：

```text
权限：主体能不能做这个动作
空间：动作只能在什么范围和上限内运行
```

权限通过但路径超出工作区时拒绝；路径在工作区内但主体无权访问时同样拒绝。空间合同不能替代权限策略，权限策略也不能替代真实路径、进程和资源限制。

## 常见失败

| 失败行为 | 保护方式 |
|---|---|
| `../../` 或符号链接越界 | 解析最终路径后拒绝 |
| 读取未挂载的宿主文件 | 物理挂载和执行器检查共同限制 |
| 命令启动后台进程 | 限制进程树并支持统一回收 |
| 访问未允许的域名 | 网络策略阻断并记录 |
| 写入超大文件 | 配额拒绝，保留已写范围 |
| 沙箱内访问错误租户目录 | 挂载和租户范围双重校验 |
| 任务恢复复用旧句柄 | 重新创建空间并重新绑定策略 |
| 临时文件被当作最终产物 | 只有登记产物允许导出 |
| 进程被杀但外部请求已生效 | 标记状态未知，先查询再处理 |

## 什么时候需要完整沙箱

纯文本生成、只读且资料已经在服务端过滤、没有文件或网络副作用的短任务，可以只使用基础资源和权限校验。

只要 Agent 能执行命令、读写用户文件、访问外部网络或生成可交付产物，就需要明确工作区和资源边界。隔离应在第一次产生副作用之前建立，而不是等出现越界后再补救。

## 如何验收操作空间

重点验证真实执行范围：

- 路径规范化和符号链接检查能阻止越界；
- 未挂载的宿主文件和其他租户目录不可访问；
- 命令、子进程和后台进程可以被限制和回收；
- 未允许的域名和端口无法建立连接；
- CPU、内存、磁盘、文件大小和并发达到上限后有明确出口；
- 任务取消或策略变化后，旧句柄和连接会被撤销；
- 只有登记并通过检查的产物可以导出；
- 恢复任务会重新创建并绑定操作空间；
- 进程被终止或网络超时后，未知副作用能够被记录和处理。

操作空间的目标不是让 Agent 完全不能行动，而是让每一次行动都发生在可描述、可限制、可撤销和可回放的范围内。
