# Agent 推理设计：路由、证据与假设验证

推理设计要决定一项任务值得投入多少判断成本，以及什么证据足以支持下一步。增加调用次数有时能改善结果，也可能只是重复缺少依据的猜测。每条推理路径都需要输入条件、验证方式、预算和退出状态。

以排查“导出的记录数少于查询结果”为例，Agent 可以提出过滤条件不同、分页遗漏、快照时间不一致等假设。系统需要把这些解释变成可执行检查，取得证据后再决定修改哪里。

## 一、分开业务路径、推理方式和模型选择

这三种决定相互关联，但不能合并成一个“复杂度分数”。

| 决定 | 回答的问题 | 示例 |
| --- | --- | --- |
| 业务路径 | 当前要回答、调查、形成提案，还是执行动作 | 用户只要求解释差异，还没有要求修改数据 |
| 推理方式 | 单步判断、顺序核验、并行候选还是循环调查 | 数据缺口需要查询，多个原因需要逐项排除 |
| 模型与预算 | 哪种能力、多少时间和调用资源足够 | 简单分类可用较低成本配置，复杂分析给予更多预算 |

高风险动作可能很短，例如删除一张表；复杂研究也可能完全只读。推理难度不能直接决定执行权限。换更强的模型，同样不能替代缺失的业务对象、当前状态或有效授权。

## 二、路由同时看意图、证据、对象和风险

一次路由至少核对四项信号。意图说明用户要完成什么；证据状态说明目前知道多少；执行对象说明具体作用于谁、是否已经确定；动作风险说明会产生什么后果。

对于“查一下导出问题，顺便修好”，可以拆成调查与修改两段。调查阶段读取限定数据并验证假设；修改阶段消费已确认原因和具体变更提案。若调查未取得足够证据，就保留缺口，不能把模糊请求直接路由到写操作。

路由结果应保存选中路径、必要输入、调用和时间预算、阻塞原因、升级条件、退出方式及策略版本。模型给出的置信度只能作为参考信号，不能独立成为高影响动作的放行依据。

对于候选范围明确的分类问题，可用专门的分类或打分组件缩小候选集。但候选集本身要覆盖合法路径，并提供拒判或未知出口。判断组件“能选一个”不代表它知道当前问题是否在候选范围内。

## 三、让中间判断可以被核验

可核验的判断记录应包含命题、证据引用、计算或检查结果、适用条件、局部结论与未决项。它是面向任务的简明依据，不要求保存模型内部的完整思维过程。

例如“导出缺少 120 条记录”要绑定查询快照、过滤条件、记录主键集合和差集结果。模型可以解释差集代表什么，数量和集合比较则交给程序独立计算。

需要设置三类检查：

| 检查 | 通过条件 | 不通过时的处理 |
| --- | --- | --- |
| 证据适用性 | 对象、时间、版本和权限适用于当前问题 | 换源、刷新或明确缺口 |
| 可复算性 | 可计算部分能用程序或独立规则复核 | 修正计算、检查单位和输入 |
| 结论覆盖 | 证据足以支持结论强度，必要限制未遗漏 | 降低结论强度、补证或退出 |

结果正确和原因正确也要分开。一项修改让导出条数恢复，只能证明该条件下结果改善；若没有控制其他变量，不能直接认定全部历史问题都由同一个原因引起。

## 四、并行探索要明确分支为什么不同

并行探索适合比较候选解释或方案。分支可以采用不同假设、不同证据源或不同实现办法，而不是复制同一段提示词后投票。

在导出故障中，可以让三个候选方向分别检查过滤条件、分页与数据快照。每个方向返回自己的前提、检查结果、证据版本、解释范围和反例，统一验证后再决定下一步。分支只读排查时较容易隔离；若要试补丁，应使用独立工作区和统一基线。

三份结果引用同一条日志，不能算三份独立证据。不同分支讨论不同时间窗，也不能直接比较置信分。聚合先对齐对象、时间和口径，再判断结论是否真正冲突。

多数票适用于已经定义好共同问题和判定标准的候选比较。真实规则冲突、证据缺失或权限不清，应进入裁决或补证流程；重复采样不能把这些问题消除。

## 五、把假设变成能支持或削弱它的检查

### 1、提出假设时同时写验证条件

| 假设 | 有区分力的检查 | 结果如何改变判断 |
| --- | --- | --- |
| 过滤条件不一致 | 在同一快照上比较两端实际使用的条件 | 条件差异解释缺失集合时支持；条件一致时削弱 |
| 分页漏取 | 比较每页范围、游标和去重后的主键集合 | 缺口对应页边界时支持；完整覆盖时削弱 |
| 数据时间不同 | 对齐查询与导出快照后重算差集 | 同快照后差异消失，支持时间差解释 |

检查应能区分候选原因。再读一遍同样的报错，通常不能在这几个假设之间提供新信息。

### 2、把未证实、被削弱和已证伪分开

查不到分页日志，只说明缺证。一次小样本导出正常，也不能排除大数据量下的分页问题。证伪需要检查覆盖了假设所声称的条件；否则保留为未决或降低可信度。

确认的事实也有版本与时间范围。新证据可以显式修订旧判断，但要留下更正理由。若新事实改变了整个调查方向，重建候选假设，同时保留仍有效的事实、已排除条件和历史消耗。

### 3、停止由证据与预算共同决定

循环应在以下任一条件成立时结束：业务验收达到要求；关键问题缺少可取得的证据；连续检查没有新增有效信息；预算耗尽；下一步需要超出现有权限。

停止时交付当前结论、适用范围、证据引用、剩余假设和建议的下一项检查。不要为了输出确定答案，把“最可能”写成“已经证实”。

## 六、用整项任务的结果衡量推理投入

比较不同路由和推理方式时，保持任务切片、输入和验收标准一致，记录验证通过率、误判、合理退出、总成本与耗时。随机性较强的任务需要重复运行，观察波动和失败分布。

成本统计包含失败尝试、分支探索、升级与重试，再除以经验证成功的任务数。只有成功任务的模型费用，会漏掉最昂贵的失败路径；没有成功任务时，该比值不可计算，应直接报告总消耗。

可以从一条串行核验路径开始。只有当不同候选检查确实能够并行、聚合标准清楚，或者现有判断质量达不到要求时，再增加分支或模型预算。循环的运行控制见 [Agent Loop](./agent-brain.md)，跨执行者的结果收口见[多 Agent 协作](./agent-multi-agent-orchestration.md)。
