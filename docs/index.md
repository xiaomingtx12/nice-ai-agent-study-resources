# Nice AI 学习沉淀

<section className="home-lead">

  <p>把优秀学习资源和真实开源项目，变成人能复用、AI 能调用的工程判断。</p>

  <p>能交给 AI 做的交给 AI，方向和判断留在人手里。真正在循环的是应用拆解和方法复盘两栏——拆项目、抽技巧、攒出更好的工程判断；资源导航是旁边随时可查的参考底座，不在环上。</p>

</section>

## 循环在哪两栏之间，资源在哪

```mermaid
flowchart LR
  R["资源导航<br/>随时可查的参考底座 · 不在环上"]
  A["应用拆解<br/>人先判断值得拆哪一点<br/>AI 再沿方向深挖"]
  M["方法与复盘<br/>抽 agent 工程技巧<br/>攒出可复用的工程判断"]
  R -. "卡住时补认知（按需）" .-> A
  R -. "卡住时补认知（按需）" .-> M
  A == "拆完抽技巧" ==> M
  M -. "目标：技巧沉成 skill 回喂下一轮（未通）" .-> A
```

<section className="home-loop-thesis">
  <p>为什么这么分工：AI 存着海量专业知识、能预测能梳理，但要人给特定输入才激活对应那部分，而且它按概率把最像的东西铺出来，越顺越可能在自信地出错；人反过来能判断真伪却知识有限。两者缺口互补，所以是<strong>人定方向、AI 铺广度、人验真伪</strong>——判断的入口和出口都在人手里，AI 把中间那段做得又快又全。</p>
  <p>真正在循环的只有两栏：应用拆解和方法复盘。拆项目、抽出技巧、把技巧沉成能带到下一次的工程判断——判断这个 loop 有没有真跑起来，只看一条：<strong>第 N+1 轮，是不是因为第 N 轮的产出而判断更准、拆得更透了。</strong>是，才叫前进；只是文章变多，是堆积。前提是抽出的技巧真变成被下一轮调用的 skill，而不是躺在文档里的一段话。<strong>说实话，这条回箭头现在还没通</strong>——skill 还没封、工作流还没搭，图里标成「未通」就是这个意思。资源导航不在这个环里，它是拆解和复盘卡住时随时去查的参考底座。</p>
</section>

## 怎么用这个站

- 找资源学：从资源导航的地图按缺口选一条。
- 看系统怎么拆：进应用拆解，对照 Dify 或 Claude Code 的实现，看它为什么这样拆。
- 沉淀方法论：方法与复盘里的跨项目判断和 agent 工程技巧，可对照自己的实践。

<p className="home-route-meta">内容在，商业项目线刚起步，skill 和工作流还没落地。首页写的是这个站要长成的样子和为什么这么建，等最小循环（人定方向 → AI 沿方向拆 → 抽 skill → 下一轮真调用它）跑通一圈，再把 skill 那一步从方向升级成事实。</p>

## 这个站怎么写

<section className="home-principles">
  <ul>
    <li>能交给 AI 做的交给 AI，方向和判断留给人；AI 铺出来的东西，人要验真伪再入库。</li>
    <li>产物为复用而结构化：人能读懂，AI 能抽取、能调用，同一份东西两种读法。</li>
    <li>不追求全，收录认为值得反复回看的东西。</li>
    <li>不写平均用力的总结，每篇都尽量给出明确判断。</li>
    <li>不搬运原文，优先留下对应的理解、取舍和以后还会回看的笔记。</li>
  </ul>
</section>
