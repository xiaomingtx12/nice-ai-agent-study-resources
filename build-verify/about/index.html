关于我

你好，我是这个站点的维护者。

这个站点本质上是我一边学、一边拆、一边沉淀出来的 AI 应用学习仓库。它不是单纯的资源收藏夹，也不是为了把文档写得很漂亮，而是想逼自己把真正有价值的东西留下来。

GitHub​

  • GitHub 主页：https://github.com/xiaomingtx12
  • 当前仓库：https://github.com/xiaomingtx12/nice-ai-agent-study-resources

我的技术路线​

大一​

从前端入门编程，先学前端三件套，再继续往 Vue 这些框架扩展。

这一段给我的最大收获，不是“会写页面”本身，而是第一次建立了对交互、组件和用户感知的直觉。

大二​

开始把技术栈往 Java 后端扩展。

主要补了 Spring 这一套，以及 JUC、JVM、微服务、分布式、中间件这些更偏系统和工程化的内容。也正是从这时候开始，我对“一个系统为什么要这么组织”这类问题越来越有兴趣。

后面一段​

参与过一段全栈开发相关的实习。

这段经历让我更清楚地感受到，前端、后端、接口、状态、部署、协作这些东西在真实环境里是怎么连起来的。也让我慢慢不再满足于只会做单点技术题。

再往后​

开始持续接触 AI 应用。

一开始是从 Spring AI 这类更贴近原来后端栈的东西切进去，后面逐渐扩到 Python 生态里的 LangChain、LangGraph，再到更具体的 Agent 应用和 coding agent 相关内容。

到这里我才越来越明确：我真正感兴趣的，不只是“模型能不能调通”，而是 AI 应用怎么和系统设计、工具链、运行时、产品体验揉到一起。

我现在在持续学什么​

  • AI 应用与 Agent 系统
  • 后端架构和系统设计
  • coding agent / agent harness / control plane 这类更偏产品系统的问题

这些东西对我来说不是彼此割裂的。越往后看，越会发现它们其实会不断汇到一起。

我最近的一个变化​

最近有一个很明显的体会：不能只停在技术视角。

以前很容易把注意力放在“这个功能怎么做”“这个架构怎么拆”上。但越学越觉得，如果没有一点产品思维，很多努力最后都很难落到真正有价值的问题上。

所以我后面也会更刻意地去想：

  • 这个方向到底解决了什么真实问题
  • 它是不是值得被做
  • 它的价值、边界和代价分别是什么

我希望自己后面做什么​

持续探索 AI 应用和后端架构相关的问题，同时也希望慢慢从“会学、会做”走到“能做出一些真的有意思、也有实际价值的东西”。

如果这个站点后面能沉淀出越来越多这种东西，那它对我来说就不是单纯的学习记录，而是真正有用了。
